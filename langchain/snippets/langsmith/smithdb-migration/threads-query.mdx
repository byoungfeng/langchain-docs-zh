## 线程：查询

查询项目内的线程，支持基于游标的分页。返回匹配给定时间范围和可选过滤条件的线程。

### 主要变更

#### 方法名

<Tabs>
  <Tab title="Python">
    | 旧版 | 新版 |
    |------|------|
    | `client.list_threads()` | `client.threads.query()` |

    <Note>
    `client.threads.query()` 现在为异步。需通过 `await` 调用。
    </Note>

    参见 [参考文档](https://reference.langchain.com/python/langsmith/_openapi_client/resources/threads/ThreadsResource/query) 获取完整参数和字段列表。
  </Tab>
  <Tab title="TypeScript">
    | 旧版 | 新版 |
    |------|------|
    | `client.listThreads()` | `client.threads.query()` |

    参见 [参考文档](https://reference.langchain.com/javascript/langsmith/_openapi_client/Langsmith/Threads/query) 获取完整参数和字段列表。
  </Tab>
  <Tab title="Java">
    <Note>
Java 原先没有专门的线程列表方法。最接近的遗留方案是通过 `thread_id` 元数据手动分组通用查询。
    </Note>

    | 旧版 | 新版 |
    |------|------|
    | `client.runs().query()` (通用，客户端端分组) | `client.threads().query()` |

    参见 [参考文档](https://javadoc.io/doc/com.langchain.smith/langsmith-java/latest/com/langchain/smith/services/blocking/ThreadService.html) 获取完整参数列表。
  </Tab>
  <Tab title="Go">
    <Note>
Go 原先没有专门的线程列表方法。最接近的遗留方案是通过 `thread_id` 元数据手动分组通用查询。
    </Note>

    | 旧版 | 新版 |
    |------|------|
    | `client.Runs.Query()` (通用，客户端端分组) | `client.Threads.Query()` |

    参见 [API 文档](https://pkg.go.dev/github.com/langchain-ai/langsmith-go#ThreadService.QueryAutoPaging) 获取完整参数列表。
  </Tab>
  <Tab title="cURL">
    | 旧版 | 新版 |
    |------|------|
    | `POST /api/v1/runs/query` (`is_root=true`, 客户端端分组) | `POST /api/v2/threads/query` |

    参见 [参考文档](https://docs.langchain.com/langsmith/smith-api/threads/query-threads) 获取完整参数和字段列表。
  </Tab>
</Tabs>

#### 查询参数

<Tabs>
  <Tab title="Python">
    | 旧版 (`list_threads`) | 新版 (`threads.query`) | 备注 |
    |---|---|---|
    | `project_id` XOR `project_name` | `project_id` | 新方法仅接受 UUID；需先通过 `aread_project()` 解析名称，与 `Runs: query` 模式一致 |
    | `start_time` (默认1天前) | `min_start_time` + `max_start_time` | 可选；默认为以当前时间结束的1天窗口，与 `start_time` 一致 |
    | `offset` + `limit` | `cursor` + `page_size` | 偏移分页替换为游标分页 |
    | `filter` (基于 runs) | `filter` | 同样语法；现在基于每个线程的根 runs 评估 |
  </Tab>
  <Tab title="TypeScript">
    | 旧版 (`listThreads`) | 新版 (`threads.query`) | 备注 |
    |---|---|---|
    | `projectId` XOR `projectName` | `project_id` | 新方法仅接受 UUID；需先通过 `readProject()` 解析名称 |
    | `startTime` (默认1天前) | `min_start_time` + `max_start_time` | 可选；默认为以当前时间结束的1天窗口，与 `startTime` 一致 |
    | `offset` + `limit` | `cursor` + `page_size` | 偏移分页替换为游标分页 |
    | `filter` | `filter` | 同样语法；现在基于每个线程的根 runs 评估 |
  </Tab>
  <Tab title="Java">
    无需映射查询参数。原方法不存在。旧方案使用通用查询（`is_root=true`，通过 `thread_id` 元数据手动分组）。`threads().query()` 接受 `projectId`, `minStartTime`, `maxStartTime`（两者可选，默认为以当前时间结束的1天窗口），`filter`, `pageSize`, `cursor`。
  </Tab>
  <Tab title="Go">
    无需映射查询参数。原方法不存在。旧方案使用通用查询（`IsRoot: true`，通过 `thread_id` 元数据手动分组）。`Threads.Query()` 接受 `ProjectID`, `MinStartTime`, `MaxStartTime`（两者可选，默认为以当前时间结束的1天窗口），`Filter`, `PageSize`, `Cursor`。
  </Tab>
  <Tab title="cURL">
    `POST /api/v2/threads/query` 主体字段：`project_id`, `min_start_time`（可选），`max_start_time`（可选），`filter`, `page_size`, `cursor`（均需 `snake_case`）。`min_start_time`/`max_start_time` 默认为以当前时间结束的1天窗口（当省略时）。
  </Tab>
</Tabs>

#### 响应字段

<Tabs>
  <Tab title="Python">
    Python 的遗留 `ListThreadsItem` 仅包含 `thread_id`, `runs`（完整嵌入 `Run[]`），`count`, `min_start_time`, `max_start_time`。完全不包含 Token/cost/latency/feedback 字段。

新的 `Thread` 从不嵌入完整的运行列表（这正是 `threads.list_traces` 的作用），而是添加真实的 `feedback_stats`、`latency_p50`/`latency_p99`、按类别 `_details`、`first_trace_id`/`last_trace_id`、`first_inputs`/`last_outputs` 预览，以及 `last_error`、`num_errored_turns`。

    | Before (legacy `ListThreadsItem`) | After (new `Thread`) | Notes |
    |---|---|---|
    | `thread_id` | `thread_id` | Unchanged |
    | `runs` (full embedded `Run[]`) | *(not available)* | Use `threads.list_traces` for per-trace detail |
    | `count` | `count` | Unchanged |
    | `min_start_time` | `min_start_time` | Unchanged |
    | `max_start_time` | `max_start_time` | Unchanged |
    | *(not available)* | `start_time` | New: a reference start time for this row, for example for sorting |
    | *(not available)* | `trace_id` | New: a representative root trace UUID, for example for deep links |
    | *(not available)* | `first_trace_id`, `last_trace_id` | New: chronologically first/last trace UUID in the query window |
    | *(not available)* | `first_inputs`, `last_outputs` | New: truncated previews from the first/last trace |
    | *(not available)* | `last_error` | New |
    | *(not available)* | `num_errored_turns` | New |
    | *(not available)* | `latency_p50`, `latency_p99` | New |
    | *(not available)* | `total_tokens`, `total_cost` | New |
    | *(not available)* | `total_token_details`, `total_cost_details` | New: per-category dicts, unlike `threads.list_traces` these are not wrapped in `.raw` |
    | *(not available)* | `feedback_stats` | New |
