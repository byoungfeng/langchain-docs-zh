## 线程：列出追踪

检索项目中特定线程的所有追踪记录。

### 主要变更

#### 方法名称

<Tabs>
  <Tab title="Python">
    | 之前 | 之后 |
    |------|------|
    | `client.read_thread()` | `client.threads.list_traces()` |

    <Note>
    `client.threads.list_traces()` 现在为异步。需通过 `await` 调用。
    </Note>

    参见 [参考文档](https://reference.langchain.com/python/langsmith/_openapi_client/resources/threads/ThreadsResource/list_traces)] 获取完整参数和字段列表。
  </Tab>
  <Tab title="TypeScript">

  </Tab>

    <Note>Java 始终没有专用的线程级方法。最接近的遗留等效方案是通过 `thread_id` 元数据约定过滤通用查询。</Note>

#### 查询参数

<Tabs>
  <Tab title="Python">
    `read_thread` 的 `is_root` 没有新等效实现。`list_traces` 始终只返回根运行（根追踪）结果，名称匹配其功能。`read_thread` 的 `order`（升序/降序）同样没有新等效实现：结果始终按 `start_time` 升序排列，采用固定服务端顺序。

    | 之前 (`read_thread`) | 之后 (`list_traces`) | 备注 |
    |---|---|---|
    | `thread_id` | `thread_id` (路径参数) | 保持不变 |
    | `project_id` XOR `project_name` | `project_id` | 新方法仅接受 UUID |
    | `is_root` | *(不可用)* | 新方法始终只返回根运行结果 |
    | `order` | *(不可用)* | 新方法无排序/排序字段 |
    | `filter` | `filter` | 语法相同，现作用于每个根追踪运行 |
    | `select` (任意运行字段列表) | `selects` | 新方法使用 `ThreadTraceSelectField`（24 个大写枚举值） |
    | *(不可用)* | `page_size` + `cursor` | 新方法新增游标分页 |

  </Tab>
  <Tab title="TypeScript">
    `readThread` 的 `isRoot` 没有新等效实现。`listTraces` 始终只返回根运行（根追踪）结果，名称匹配其功能。`readThread` 的 `order`（升序/降序）同样没有新等效实现：结果始终按 `start_time` 升序排列，采用固定服务端顺序。

| 之前 (`readThread`) | 之后 (`listTraces`) | 备注 |
    |---|---|---|

    | `order` | *(不可用)* | 新方法无排序/顺序字段 |
    | `filter` | `filter` | 同样语法，现针对每个根运行追踪评估 |
    | `select` (任意运行字段列表) | `selects` | 新方法使用 24 值大写枚举 |
    | *(不可用)* | `page_size` + `cursor` | 新方法添加游标分页 |
  </Tab>
  <Tab title="Java">

  </Tab>
