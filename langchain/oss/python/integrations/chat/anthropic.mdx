## 安装

要访问 Anthropic (Claude) 模型，您需要安装 `langchain-anthropic` 集成包并获取一个 [Claude](https://platform.claude.com/docs/en/get-started#prerequisites) API 密钥。

### 安装

<CodeGroup>
    ```bash pip
    pip install -U langchain-anthropic
    ```
    ```bash uv
    uv add langchain-anthropic
    ```
</CodeGroup>

### 凭证

前往 [Claude 控制台](https://console.anthropic.com) 注册并生成一个 Claude API 密钥。完成此操作后，设置 `ANTHROPIC_API_KEY` 环境变量：

```python
import getpass
import os

if "ANTHROPIC_API_KEY" not in os.environ:
    os.environ["ANTHROPIC_API_KEY"] = getpass.getpass("Enter your Anthropic API key: ")
```

要启用模型调用的自动跟踪，设置您的 [LangSmith](https://docs.langchain.com/langsmith/observability) API 密钥：

```python
os.environ["LANGSMITH_API_KEY"] = getpass.getpass("Enter your LangSmith API key: ")
os.environ["LANGSMITH_TRACING"] = "true"
```

## 采样参数

较新的 Claude 模型会拒绝非默认的采样参数。在 `claude-opus-5`、`claude-fable-5`、`claude-opus-4-8`、`claude-opus-4-7` 或 `claude-sonnet-5` 上将 `temperature`、`top_p` 或 `top_k` 设置为非默认值会返回 400 错误：

```python
from langchain_anthropic import ChatAnthropic

model = ChatAnthropic(model="claude-opus-5", temperature=0)
model.invoke("Hello!")
# anthropic.BadRequestError: Error code: 400 -
# {'type': 'error', 'error': {'type': 'invalid_request_error',
#  'message': '`temperature` is deprecated for this model.'}}
```

模型支持情况：

| 模型 | `temperature` / `top_p` / `top_k` |
| --- | --- |
| `claude-opus-5`、`claude-fable-5`、`claude-opus-4-8`、`claude-opus-4-7`、`claude-sonnet-5` | 拒绝非默认值 (400)。省略参数，或仅传递默认值（例如，`temperature=1`）。 |
| `claude-opus-4-6`、`claude-sonnet-4-6`、`claude-haiku-4-5` 及更早版本 | 被接受 |

<Warning>
    **升级模型字符串？**

    按 `ChatAnthropic(model=..., temperature=0)` 编写的代码在升级到上述较新模型时会失效。请移除采样参数，而不是调整其值。在这些模型上，应通过提示词来控制输出风格。详情请参阅 [Anthropic 迁移指南](https://platform.claude.com/docs/en/about-claude/models/migration-guide)。

</Warning>

## 内容块

在使用工具时，[扩展思考](#扩展思考)和其他功能，来自单个 Anthropic @[`AIMessage`] 的内容可以是单个字符串，也可以是 Anthropic 内容块的列表。

例如，当 Anthropic 模型调用工具时，工具调用是消息内容的一部分（同时也会在标准化的 @[`AIMessage.tool_calls`] 中暴露）：

```python
from langchain_anthropic import ChatAnthropic
from typing_extensions import Annotated

model = ChatAnthropic(model="claude-haiku-4-5-20251001")


def get_weather(
    location: Annotated[str, ..., "Location as city and state."]
) -> str:
    """Get the weather at a location."""
    return "It's sunny."


model_with_tools = model.bind_tools([get_weather])
response = model_with_tools.invoke("Which city is hotter today: LA or NY?")
response.content
```

## 工具

Anthropic 的工具使用功能允许您定义 Claude 在对话期间可以调用的外部函数。这支持动态信息检索、计算以及与外部系统的交互。

有关如何将工具绑定到您的模型实例的详细信息，请参见 @[`ChatAnthropic.bind_tools`]。

<Note>
    有关 Claude 的内置工具（代码执行、网络浏览、文件 API 等）的信息，请参阅 [内置工具](#内置工具)。
</Note>

```python
from pydantic import BaseModel, Field


class GetWeather(BaseModel):
    '''Get the current weather in a given location'''

    location: str = Field(description="The city and state, e.g. San Francisco, CA")


class GetPopulation(BaseModel):
    '''Get the current population in a given location'''

    location: str = Field(description="The city and state, e.g. San Francisco, CA")


model_with_tools = model.bind_tools([GetWeather, GetPopulation]) # [!code highlight]
ai_msg = model_with_tools.invoke("Which city is hotter today and which is bigger: LA or NY?")
ai_msg.tool_calls
```

### 严格工具使用

<Info>
    严格工具使用需要 `langchain-anthropic>=1.1.0`。有关受支持的模型，请参阅 [Claude 文档](https://platform.claude.com/docs/en/agents-and-tools/tool-use/strict-tool-use)。
</Info>

Anthropic 支持选择加入 [严格遵循工具调用模式](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)。这通过约束解码确保工具名称和参数经过验证并正确类型化。

在没有严格模式的情况下，Claude 有时可能会生成无效的工具输入，从而破坏您的应用程序：

- **类型不匹配**：`passengers: "2"` 而不是 `passengers: 2`
- **缺少必需字段**：遗漏您的函数期望的字段
- **无效的枚举值**：超出允许范围的值
- **模式违规**：嵌套对象不符合预期结构

严格工具使用保证符合模式的工具调用：

- 工具输入严格遵循您的 `input_schema`
- 保证字段类型和必需字段
- 消除对格式错误输入的错误处理
- 使用的工具 `name` 始终来自提供的工具

| 使用严格工具使用 | 使用标准工具调用 |
|---------------------|---------------------------|
| 构建可靠性至关重要的智能体工作流 | 简单的单轮工具调用 |
| 具有许多参数或嵌套对象的工具 | 原型设计和实验 |
| 需要特定类型的功能（例如，`int` vs `str`） |  |

要启用严格工具使用，请在调用 @[`bind_tools`][ChatAnthropic.bind_tools] 时指定 `strict=True`。

```python
from langchain_anthropic import ChatAnthropic

model = ChatAnthropic(model="claude-sonnet-4-6")

def get_weather(location: str) -> str:
    """Get the weather at a location."""
    return "It's sunny."

model_with_tools = model.bind_tools([get_weather], strict=True)  # [!code highlight]
```

<Accordion
    title="示例：类型安全的预订系统"
>
    考虑一个 `passengers` 必须是整数的预订系统：

    ```python
    from langchain_anthropic import ChatAnthropic
    from typing import Literal

    model = ChatAnthropic(model="claude-sonnet-4-6")

    def book_flight(
        destination: str,
        departure_date: str,
        passengers: int, # [!code highlight]
        cabin_class: Literal["economy", "business", "first"]
    ) -> str:
        """Book a flight to a destination.

        Args:
            destination: The destination city
            departure_date: Date in YYYY-MM-DD format
            passengers: Number of passengers (must be an integer)
            cabin_class: The cabin class for the flight
        """
        return f"Booked {passengers} passengers to {destination}"

    model_with_tools = model.bind_tools(
        [book_flight],
        strict=True, # [!code highlight]
        tool_choice="any",
    )
    response = model_with_tools.invoke("Book 2 passengers to Tokyo, business class, 2025-01-15")

    # With strict=True, passengers is guaranteed to be int, not "2" or "two"
    print(response.tool_calls[0]["args"]["passengers"])
    ```

</Accordion>

严格工具使用有一些 JSON 模式限制需要注意。有关更多详细信息，请参阅 [Claude 文档](https://platform.claude.com/docs/en/build-with-claude/structured-outputs#json-schema-limitations)。

如果您的工具模式使用不受支持的功能，您将收到 400 错误。在这种情况下，请简化模式或使用标准（非严格）工具调用。

### 输入示例

对于复杂的工具，您可以提供使用示例以帮助 Claude 正确理解如何使用它们。这是通过在工具的 `extras` 参数中设置 `input_examples` 实现的。

```python
from langchain_anthropic import ChatAnthropic
from langchain.tools import tool

@tool(
    extras={ # [!code highlight]
        "input_examples": [ # [!code highlight]
            { # [!code highlight]
                "query": "weather report", # [!code highlight]
                "location": "San Francisco", # [!code highlight]
                "format": "detailed" # [!code highlight]
            }, # [!code highlight]
            { # [!code highlight]
                "query": "temperature", # [!code highlight]
                "location": "New York", # [!code highlight]
                "format": "brief" # [!code highlight]
            } # [!code highlight]
        ] # [!code highlight]
    } # [!code highlight]
)
def search_weather_data(query: str, location: str, format: str = "brief") -> str:
    """Search weather database with specific query and format preferences.

    Args:
        query: The type of weather information to retrieve
        location: City or region to search
        format: Output format, either 'brief' or 'detailed'
    """
    return f"{format.title()} {query} for {location}: Data found"

model = ChatAnthropic(model="claude-sonnet-4-6")
model_with_tools = model.bind_tools([search_weather_data])

response = model_with_tools.invoke(
    "Get me a detailed weather report for Seattle"
)
```

`extras` 参数还支持：
- `defer_loading` (bool): 按需加载工具，用于 [工具搜索](#工具搜索) 或 [会话中期的工具变更](#对话中更改工具)
- `cache_control` (dict): 为该工具启用 [提示词缓存](#缓存工具)
- `eager_input_streaming` (bool): 为该工具启用 [细粒度工具流式输出](#细粒度工具流式输出)

### 细粒度工具流式输出

Anthropic 支持 [细粒度工具流式输出](https://platform.claude.com/docs/en/agents-and-tools/tool-use/fine-grained-tool-streaming)，在流式传输具有大参数的工具调用时可以减少延迟。

细粒度流式输出在参数数据可用时立即发送，而不是在传输前缓存整个参数值。对于大型工具参数，这可以将初始延迟从 15 秒减少到约 3 秒。

<Warning>
    细粒度流式输出可能会返回无效或部分 JSON 输入，特别是如果响应在完成前就到达 `max_tokens` 时。为不完整的 JSON 数据实现适当的错误处理。
</Warning>

要为应增量流式传输工具参数的工具启用细粒度工具流式输出，请在工具上设置 `extras={"eager_input_streaming": True}`。该值会通过工具定义传递给 Anthropic API。

```python
from langchain_anthropic import ChatAnthropic
from langchain.tools import tool

model = ChatAnthropic(model="claude-sonnet-4-6")

@tool(extras={"eager_input_streaming": True})
def write_document(title: str, content: str) -> str:
    """Write a document with the given title and content."""
    return f"Document '{title}' written successfully"

model_with_tools = model.bind_tools([write_document])

# Stream tool calls with reduced latency
for chunk in model_with_tools.stream(
    "Write a detailed technical document about the benefits of streaming APIs"
):
    print(chunk.content)
```

流式数据以 `input_json_delta` 块的形式到达 `chunk.content`。您可以累积这些块来构建完整的工具参数：

```python
import json

from langchain_anthropic import ChatAnthropic
from langchain.tools import tool

model = ChatAnthropic(model="claude-sonnet-4-6")

@tool(extras={"eager_input_streaming": True})
def write_document(title: str, content: str) -> str:
    """Write a document with the given title and content."""
    return f"Document '{title}' written successfully"

model_with_tools = model.bind_tools([write_document])

accumulated_json = ""

for chunk in model_with_tools.stream("Write a document about AI"):
    for block in chunk.content:
        if isinstance(block, dict) and block.get("type") == "input_json_delta":
            accumulated_json += block.get("partial_json", "")
            try:
                # Try to parse accumulated JSON
                parsed = json.loads(accumulated_json)
                print(f"Complete args: {parsed}")
            except json.JSONDecodeError:
                # JSON is still incomplete, continue accumulating
                pass
```

```text
Complete args: {'title': 'Artificial Intelligence: An Overview', 'content': '# Artificial Intelligence: An Overview...
```

### 程序化工具调用

<Info>
    程序化工具调用需要 `langchain-anthropic>=1.3.0`。请参阅 [Claude 文档](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling) 了解支持的模型。
</Info>

工具可以配置为从 Claude 的 [代码执行](#代码执行) 环境中可调用，在涉及大数据处理或多工具工作流的环境中可以减少延迟和 Token 消耗。

有关详细信息，请参阅 Claude 的 [程序化工具调用指南](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling)。要使用此功能：

- 在您的工具集中包含 [代码执行](#代码执行) 内置工具
- 在您希望程序化调用的工具上指定 `extras={"allowed_callers": ["code_execution_20250825"]}`

下方提供了包含 [`create_agent`](/langchain/oss/langchain/agents) 的完整示例。

<Tip>
    您可以在初始化时指定 `reuse_last_container` 以自动重用先前模型响应的代码执行容器。
</Tip>

```python
from langchain.agents import create_agent
from langchain.tools import tool
from langchain_anthropic import ChatAnthropic


@tool(extras={"allowed_callers": ["code_execution_20250825"]}) # [!code highlight]
def get_weather(location: str) -> str:
    """Get the weather at a location."""
    return "It's sunny."

tools = [
    {"type": "code_execution_20250825", "name": "code_execution"}, # [!code highlight]
    get_weather,
]

model = ChatAnthropic(
    model="claude-sonnet-4-6",
    reuse_last_container=True,  # [!code highlight]
)

agent = create_agent(model, tools=tools)

input_query = {
    "role": "user",
    "content": "What's the weather in Boston?",
}

result = agent.invoke({"messages": [input_query]})
```

### 支持的输入方法

## 努力程度

某些 Claude 模型支持一个 [努力程度](https://platform.claude.com/docs/en/build-with-claude/effort) 功能，该功能控制 Claude 在响应时使用的 Token 数量。这对于在响应质量、延迟和成本之间取得平衡非常有用。

<Info>
    **模型支持**

    努力程度通常在 Claude Opus 4.6 和 Claude Opus 4.5 上可用。`max` 努力程度级别仅在 Claude Opus 4.6 上受支持。`xhigh` 努力程度级别在 Claude Opus 4.7 上受支持。Anthropic 可能会随着时间的推移添加或调整模型支持——请使用 [Claude 努力程度文档](https://platform.claude.com/docs/en/build-with-claude/effort) 作为事实来源。
</Info>

```python
from langchain_anthropic import ChatAnthropic

model = ChatAnthropic(
    model="claude-opus-4-5-20251101",
    effort="medium",  # Options: "max", "xhigh", "high", "medium", "low" [!code highlight]
)

response = model.invoke("Analyze the trade-offs between microservices and monolithic architectures")
```

<Note>
    将 `effort` 设置为 `"high"` 与完全省略该参数的行为完全相同。
</Note>

`effort` 是标准 [`reasoning_effort`](/langchain/oss/langchain/models#推理) 参数的别名，在构建和调用时都适用。如果两者都设置，`effort` 会优先。

<Note>
    `reasoning_effort` 需要 `langchain-anthropic>=1.5.3`。
</Note>

```python
model = ChatAnthropic(model="claude-opus-4-6")
response = model.invoke(
    "Analyze the trade-offs between microservices and monolithic architectures",
    reasoning_effort="high",
)
```

请参阅 [Claude 文档](https://platform.claude.com/docs/en/build-with-claude/effort)，了解何时使用不同的努力程度级别以及受支持的模型。

## 任务预算

Claude Opus 4.7 及更高版本支持 [任务预算](https://platform.claude.com/docs/en/build-with-claude/task-budgets)，这是针对智能体循环（思考、工具调用、工具结果和最终输出）的建议性 Token 目标。模型会看到正在运行的倒计时，并利用它来优先处理工作并优雅地完成。与 `max_tokens` 不同，任务预算不是硬性上限。

### 在工具结果中（智能体 RAG）

Claude 支持一个 [搜索结果](https://platform.claude.com/docs/en/build-with-claude/search-results) 内容块，表示对知识库或其他自定义源的查询的可引用结果。这些内容块可以以顶部行（如上述示例）和工具结果内的形式传递给 Claude。这允许 Claude 使用工具调用的结果来引用其响应的元素。

为了在工具调用响应中传递搜索结果，定义一个返回 `search_result` 内容块列表的工具，这些内容块以 Anthropic 的原生格式返回。例如：

```python
def retrieval_tool(query: str) -> list[dict]:
    """Access my knowledge base."""

    # Run a search (e.g., with a LangChain vector store)
    results = vector_store.similarity_search(query=query, k=2)

    # Package results into search_result blocks
    return [
        {
            "type": "search_result",
            # Customize fields as desired, using document metadata or otherwise
            "title": "My Document Title",
            "source": "Source description or provenance",
            "citations": {"enabled": True},
            "content": [{"type": "text", "text": doc.page_content}],
        }
        for doc in results
    ]
```

<Accordion title="End to end example with LangGraph">
    这里我们展示了一个端到端的示例，其中我们将样本文档填充到 LangChain [向量存储](/langchain/oss/python/integrations/vectorstores/) 中，并给 Claude 配备了一个查询这些文档的工具。

    此工具接受一个搜索查询和一个 `category` 字符串字面量，但任何有效的工具签名都可以使用。

    此示例需要 `langchain-openai` 和 `numpy` 已安装：

    ```bash
    pip install langchain-openai numpy
    ```

    ```python
    from typing import Literal

    from langchain.chat_models import init_chat_model
    from langchain.embeddings import init_embeddings
    from langchain_core.documents import Document
    from langchain_core.vectorstores import InMemoryVectorStore
    from langgraph.checkpoint.memory import InMemorySaver
    from langchain.agents import create_agent


    # Set up vector store
    # Ensure you set your OPENAI_API_KEY environment variable
    embeddings = init_embeddings("openai:text-embedding-3-small")
    vector_store = InMemoryVectorStore(embeddings)

    document_1 = Document(
        id="1",
        page_content=(
            "To request vacation days, submit a leave request form through the "
            "HR portal. Approval will be sent by email."
        ),
        metadata={
            "category": "HR Policy",
            "doc_title": "Leave Policy",
            "provenance": "Leave Policy - page 1",
        },
    )
    document_2 = Document(
        id="2",
        page_content="Managers will review vacation requests within 3 business days.",
        metadata={
            "category": "HR Policy",
            "doc_title": "Leave Policy",
            "provenance": "Leave Policy - page 2",
        },
    )
    document_3 = Document(
        id="3",
        page_content=(
            "Employees with over 6 months tenure are eligible for 20 paid vacation days "
            "per year."
        ),
        metadata={
            "category": "Benefits Policy",
            "doc_title": "Benefits Guide 2025",
            "provenance": "Benefits Policy - page 1",
        },
    )

    documents = [document_1, document_2, document_3]
    vector_store.add_documents(documents=documents)


    # Define tool
    async def retrieval_tool(
        query: str, category: Literal["HR Policy", "Benefits Policy"]
    ) -> list[dict]:
        """Access my knowledge base."""

        def _filter_function(doc: Document) -> bool:
            return doc.metadata.get("category") == category

        results = vector_store.similarity_search(
            query=query, k=2, filter=_filter_function
        )

        return [
            {
                "type": "search_result",
                "title": doc.metadata["doc_title"],
                "source": doc.metadata["provenance"],
                "citations": {"enabled": True},
                "content": [{"type": "text", "text": doc.page_content}],
            }
            for doc in results
        ]



    # Create agent
    model = init_chat_model("claude-haiku-4-5-20251001")

    checkpointer = InMemorySaver()
    agent = create_agent(model, [retrieval_tool], checkpointer=checkpointer)


    # Invoke on a query
    config = {"configurable": {"thread_id": "session_1"}}

    input_message = {
        "role": "user",
        "content": "How do I request vacation days?",
    }
    stream = await agent.astream_events(
        {"messages": [input_message]},
        config,
        version="v3",
    )
    async for snapshot in stream.values:
        snapshot["messages"][-1].pretty_print()
    ```

### 与文本分割器一起使用

Anthropic 还允许您使用 [自定义文档](https://platform.claude.com/docs/en/build-with-claude/citations#custom-content-documents) 类型指定自己的分割。LangChain [文本分割器](/langchain/oss/integrations/splitters/) 可以用于生成此目的的具有意义的分割。参见以下示例，其中我们分割了 LangChain `README.md`（一个 markdown 文档），并将其作为上下文传递给 Claude：

此示例需要 @[`langchain-text-splitters`] 已安装：

```bash

```

```python expandable
import requests
from langchain_anthropic import ChatAnthropic
from langchain_text_splitters import MarkdownTextSplitter


def format_to_anthropic_documents(documents: list[str]):
    return {
        "type": "document",
        "source": {
            "type": "content",
            "content": [{"type": "text", "text": document} for document in documents],
        },
        "citations": {"enabled": True},
    }


# Pull readme
get_response = requests.get(
    "https://raw.githubusercontent.com/langchain-ai/langchain/master/README.md"
)
readme = get_response.text

# Split into chunks
splitter = MarkdownTextSplitter(
    chunk_overlap=0,
    chunk_size=50,
)
documents = splitter.split_text(readme)

# Construct message
message = {
    "role": "user",
    "content": [
        format_to_anthropic_documents(documents),
        {"type": "text", "text": "Give me a link to LangChain's tutorials."},
    ],
}

# Query model
model = ChatAnthropic(model="claude-haiku-4-5-20251001")
response = model.invoke([message])
```

## 提示词缓存

Anthropic 支持 [缓存](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) 您的提示词中的元素，包括消息、工具定义、工具结果、图像和文档。这允许您重用大型文档、指令、[少量样本文档](https://docs.langchain.com/langsmith/create-few-shot-evaluators) 和其他数据，以减少延迟和成本。

在直接模型调用中启用提示词缓存有两种方法：

- **[自动缓存](#自动缓存)**：在调用时传递 `cache_control`（`model.invoke(..., cache_control=...)`）。这是提供者/API 级别的缓存：Anthropic API 将缓存断点应用于最后一个可缓存块，并在对话增长时将其向前移动。
- **[显式缓存断点](#显式缓存断点)**：将 `cache_control` 直接放置在单个内容块上，以实现对缓存内容进行细粒度、直接断点控制。

<Warning>
    仅某些 Claude 模型支持提示词缓存。有关详细信息，请参阅 [Claude 文档](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#supported-models)。
</Warning>

<Note>
    对于 LangChain 智能体，如果您希望 LangChain 优化稳定的系统提示词和工具内容，请优先使用 [`AnthropicPromptCachingMiddleware`](/langchain/oss/python/integrations/middleware/anthropic#提示词缓存)。中间件是 LangChain 智能体/容器的优化，与下面显示的调用级 `cache_control` 不同，后者镜像 Anthropic API 的行为。
</Note>

### 自动缓存

<Info>
    自动缓存需要 `langchain-anthropic>=1.4.0`。
</Info>

将 `cache_control` 作为调用参数传递，可自动缓存所有内容，包括最后一个可缓存块。对于具有相同前缀的后续请求，将自动重用缓存内容。随着对话的增长，缓存断点会向前移动，因此无需管理单个 `cache_control` 标记。

```python
from langchain_anthropic import ChatAnthropic
import requests

model = ChatAnthropic(model="claude-sonnet-4-5")

# Pull LangChain readme
get_response = requests.get(
    "https://raw.githubusercontent.com/langchain-ai/langchain/b476fdb54aa6e6f5f0b24a68c2f4a94e43b369f9/README.md"
)
readme = get_response.text

messages = [
    {
        "role": "system",
        "content": [
            {
                "type": "text",
                "text": "You are a technology expert.",
            },
            {
                "type": "text",
                "text": f"{readme}"
            },
        ],
    },
    {
        "role": "user",
        "content": "What's LangChain, according to its README?",
    },
]

response = model.invoke(
    messages,
    cache_control={"type": "ephemeral"},  # [!code highlight]
)

usage = response.usage_metadata["input_token_details"]
print(f"Usage:\n{usage}")

```

对于1小时缓存，指定 `ttl` 字段：

```python
response = model.invoke(
    messages,
    cache_control={"type": "ephemeral", "ttl": "1h"},  # [!code highlight]
)
```

### 显式缓存断点

为了实现细粒度控制，请用 `cache_control` 标记单个内容块。当您需要缓存以不同频率变化的多个部分时，这很有用。

#### 消息

```python expandable

messages = [
    {
        "role": "system",
        "content": [
            {
                "type": "text",
                "text": "You are a technology expert.",
            },
            {
                "type": "text",
                "text": f"{readme}",
                "cache_control": {"type": "ephemeral"},  # [!code highlight]
```

#### 对话应用中的增量缓存

提示词缓存可用于 [多轮对话](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#continuing-a-multi-turn-conversation) 以维持早期消息的上下文，而无需冗余处理。

我们可以通过用 `cache_control` 标记最终消息来启用增量缓存。Claude 将自动为后续消息使用之前缓存的最长前缀。

下面，我们实现了一个包含此功能的简单聊天机器人。我们遵循 LangChain 的 [聊天机器人教程](/langchain/oss/langchain/quickstart)，但添加了一个自定义的 [reducer](/langchain/oss/langgraph/graph-api#归约器)，该 reducer 会自动将每个用户消息中的最后一个内容块标记为 `cache_control`：

<Accordion title="Chatbot with incremental prompt caching">
    ```python expandable
    import requests
    from langchain_anthropic import ChatAnthropic
    from langgraph.checkpoint.memory import MemorySaver
    from langgraph.graph import START, StateGraph, add_messages
    from typing_extensions import Annotated, TypedDict


    model = ChatAnthropic(model="claude-sonnet-4-6")

    # Pull LangChain readme
    get_response = requests.get(
        "https://raw.githubusercontent.com/langchain-ai/langchain/master/README.md"
    )
    readme = get_response.text


    def messages_reducer(left: list, right: list) -> list:
        # Update last user message
        for i in range(len(right) - 1, -1, -1):
            if right[i].type == "human":
                right[i].content[-1]["cache_control"] = {"type": "ephemeral"}
                break

        return add_messages(left, right)


    class State(TypedDict):
        messages: Annotated[list, messages_reducer]


    workflow = StateGraph(state_schema=State)


    # Define the function that calls the model
    def call_model(state: State):
        response = model.invoke(state["messages"])
        return {"messages": [response]}


    # Define the (single) node in the graph
    workflow.add_edge(START, "model")
    workflow.add_node("model", call_model)

    # Add memory
    memory = MemorySaver()
    app = workflow.compile(checkpointer=memory)
    ```

## 对话中系统消息

<Note>
    对话中系统消息需要 `langchain-anthropic>=1.7.3`。
</Note>

支持的 Claude 模型接受 [对话中系统消息](https://platform.claude.com/docs/en/build-with-claude/mid-conversation-system-messages)。其指令从该点开始生效。添加一条消息不会改变之前的回合，因此不会使 [提示词缓存](#提示词缓存)失效。

一个以 @[`SystemMessage`] 开头的消息始终放在顶层 `system` 字段中。`ChatAnthropic` 在满足以下两个条件时，会在对话中自己的位置发送一个稍后的 `SystemMessage`：

- 模型支持对话中系统消息。[Claude 文档](https://platform.claude.com/docs/en/build-with-claude/mid-conversation-system-messages)列出了哪些模型支持。
- 消息紧随人类或工具消息之后，且是最后一条消息或后跟 AI 消息。

否则，`ChatAnthropic` 将消息移入顶层 `system` 字段并附带警告，该消息适用于整个对话。如果顶层系统消息已填满该字段，`ChatAnthropic` 会引发 `ValueError`。

```python
from langchain.messages import AIMessage, HumanMessage, SystemMessage
from langchain_anthropic import ChatAnthropic

model = ChatAnthropic(model="claude-opus-5-5")

response = model.invoke(
    [
        SystemMessage("You are a travel assistant."),
        HumanMessage("Suggest a day trip from Lisbon."),
        AIMessage("Sintra is a good choice: palaces, gardens, and a short train ride."),
        HumanMessage("How do I get there?"),
        SystemMessage("The user has switched to the mobile app. Keep answers under 50 words."),  # [!code highlight]
    ]
)
```

有关措辞指导和完善的放置规则，请参阅 [Claude 文档](https://platform.claude.com/docs/en/build-with-claude/mid-conversation-system-messages)。

### 对话中更改工具

<Note>
    对话中工具更改需要 `langchain-anthropic>=1.7.4`。
</Note>

对话中 `SystemMessage` 还可以添加或删除 Anthropic 的 [`tool_addition` 和 `tool_removal`](https://platform.claude.com/docs/en/build-with-claude/mid-conversation-system-messages#mid-conversation-tool-changes) 内容块。编辑请求中的 `tools` 会使整个对话的提示词缓存失效。这些块不会改变 `tools`，因此缓存的 prefix 仍然匹配。

上述 [放置和模型规则](#对话中系统消息) 适用。当 `ChatAnthropic` 无法在适当位置发送消息时，它会带有警告地丢弃工具更改块。

`ChatAnthropic` 添加了所需的 beta 头部，因此您无需设置 `betas`。

要在对话中途添加工具，使用 `extras={"defer_loading": True}` 绑定它，以便 Claude 最初看不到它。然后在 `tool_addition` 块中按名称引用它：

```python
from langchain.messages import HumanMessage, SystemMessage
from langchain.tools import tool
from langchain_anthropic import ChatAnthropic


@tool
def get_time() -> str:
    """Get the current time."""
    return "12:00"


@tool(extras={"defer_loading": True})  # [!code highlight]
def get_weather(location: str) -> str:
    """Get the current weather for a location."""
    return f"It's sunny in {location}."


model = ChatAnthropic(model="claude-opus-5-5")
model_with_tools = model.bind_tools([get_time, get_weather])

response = model_with_tools.invoke(
    [
        HumanMessage("What's the weather in San Francisco?"),
        SystemMessage(
            [
                {  # [!code highlight]
                    "type": "tool_addition",  # [!code highlight]
                    "tool": {"type": "tool_reference", "name": "get_weather"},  # [!code highlight]
                },  # [!code highlight]
            ]
        ),
    ]
)
```

API 会拒绝所有工具都被延迟的请求，因此至少绑定一个未使用 `defer_loading` 的工具。

要撤回工具，在 `tool_removal` 块中引用它。稍后的 `tool_addition` 可以再次提供它。

```python
SystemMessage(
    [
        {
            "type": "tool_removal",
            "tool": {"type": "tool_reference", "name": "get_weather"},
        },
    ]
)
```

要添加您最初未绑定的工具，[使用 `tool_definition` 内联定义](https://platform.claude.com/docs/en/build-with-claude/mid-conversation-system-messages#define-tools-in-a-message-beta)。内联定义处于 beta 版本，仅在 Claude API 上可用。

```python
from langchain.messages import HumanMessage, SystemMessage
from langchain_anthropic import ChatAnthropic

model = ChatAnthropic(model="claude-opus-5-5")

response = model.invoke(
    [
        HumanMessage("How many orders did we get yesterday?"),
        SystemMessage(
            [
                {
                    "type": "tool_addition",
                    "tool": {
                        "type": "tool_definition",  # [!code highlight]
                        "definition": {  # [!code highlight]
                            "name": "db_query",
                            "description": "Run a read-only SQL query against the analytics database.",
                            "input_schema": {
                                "type": "object",
                                "properties": {"sql": {"type": "string"}},
                                "required": ["sql"],
                            },
                        },
                    },
                },
            ]
        ),
    ]
)
```

您也可以将这些块包裹在 `non_standard` 块中，这就是 `content_blocks` 返回它们的方式。`ChatAnthropic` 对这两种形式发送相同的请求。

## 上下文管理

Anthropic 支持上下文管理功能，可自动管理模型的上下文窗口以优化性能和成本。

### 清除工具使用

```python
from langchain_anthropic import ChatAnthropic

model = ChatAnthropic(
    model="claude-sonnet-4-6",

    context_management={"edits": [{"type": "clear_tool_uses_20250919"}]}, # [!code highlight]

model_with_tools = model.bind_tools([{"type": "web_search_20260209", "name": "web_search"}])
response = model_with_tools.invoke("Search for recent developments in AI")
```

### 自动压缩

Claude Opus 4.6 及更高版本支持自动 [服务器端压缩](https://platform.claude.com/docs/en/build-with-claude/compaction)，当上下文窗口接近其限制时，会智能地压缩对话历史。这允许更长的对话而无需手动上下文管理。

<Info>
    **自动压缩要求：**

    - Claude Opus 4.6 或更高版本
    - `langchain-anthropic>=1.3.0`
    - `compact-2026-01-12` beta 标头
</Info>

```python
from langchain_anthropic import ChatAnthropic

model = ChatAnthropic(
    model="claude-opus-4-8",
    betas=["compact-2026-01-12"], # [!code highlight]
    max_tokens=4096,
    context_management={ # [!code highlight]
        "edits": [ # [!code highlight]
            { # [!code highlight]
                "type": "compact_20260112", # [!code highlight]
                "trigger": {"type": "input_tokens", "value": 50000}, # [!code highlight]
            } # [!code highlight]
        ] # [!code highlight]
    }, # [!code highlight]
)
```

请参阅 Anthropic 的文档了解 [触发配置](https://platform.claude.com/docs/en/build-with-claude/compaction#trigger-configuration) 的详细信息。

当触发压缩事件时，`ChatAnthropic` 将返回 [压缩块](https://platform.claude.com/docs/en/build-with-claude/compaction#working-with-compaction-blocks)，表示提示的状态。这些应在多轮应用程序中将消息历史传递回模型时保留。

## 结构化输出

<Info>
    结构化输出需要 `langchain-anthropic>=1.1.0`。请参阅 [Claude 文档](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)以了解支持的模型。
</Info>

Anthropic 支持一种原生的 [结构化输出功能](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)，该功能保证其响应符合给定的模式。

您可以在单独的模型调用中访问此功能，或通过指定 LangChain [智能体](/langchain/oss/langchain/agents)的 [响应格式](/langchain/oss/langchain/structured-output)来使用此功能。以下是一些示例。

<Accordion title="Individual model calls">

使用 [`with_structured_output`](/langchain/oss/langchain/models#结构化输出) 方法生成结构化模型响应。指定 `method="json_schema"` 以启用 Anthropic 的原生结构化输出功能；否则，该方法默认使用函数调用。

```python
from langchain_anthropic import ChatAnthropic
from pydantic import BaseModel, Field

model = ChatAnthropic(model="claude-sonnet-4-6")

class Movie(BaseModel):
    """A movie with details."""
    title: str = Field(description="The title of the movie")
    year: int = Field(description="The year the movie was released")
    director: str = Field(description="The director of the movie")
    rating: float = Field(description="The movie's rating out of 10")

model_with_structure = model.with_structured_output(Movie, method="json_schema")  # [!code highlight]
response = model_with_structure.invoke("Provide details about the movie Inception")
response
```

```python
Movie(title='Inception', year=2010, director='Christopher Nolan', rating=8.8)
```

</Accordion>

<Accordion title="Agent response format">

使用 [`ProviderStrategy`](/langchain/oss/langchain/structured-output) 指定 `response_format` 以在生成最终响应时启用 Anthropic 的结构化输出功能。

```python
from langchain.agents import create_agent
from langchain.agents.structured_output import ProviderStrategy
from pydantic import BaseModel

class Weather(BaseModel):
    temperature: float
    condition: str

def weather_tool(location: str) -> str:
    """Get the weather at a location."""
    return "Sunny and 75 degrees F."

agent = create_agent(
    model="anthropic:claude-sonnet-4-5",
    tools=[weather_tool],
    response_format=ProviderStrategy(Weather),  # [!code highlight]
)

result = agent.invoke({
    "messages": [{"role": "user", "content": "What's the weather in SF?"}]
})

result["structured_response"]
```

```python
Weather(temperature=75.0, condition='Sunny')
```

</Accordion>

## 内置工具

Anthropic 支持多种内置的客户端和服务器端 [工具](/langchain/oss/langchain/tools/)。

服务器端工具（例如 [web search](#网络搜索)）会被传递给模型并由 Anthropic 执行。客户端工具（例如 [bash tool](#bash-工具)）需要您在应用程序中实现回调执行逻辑，并将结果返回给模型。

无论哪种情况，您都可以通过在模型实例上使用 @[`bind_tools`][ChatAnthropic.bind_tools] 来使您的聊天模型访问工具。

重要的是，客户端工具需要您实现执行逻辑。请参考下文的相关章节获取示例。

<Info>
    **中间件与工具**

    对于客户端工具（例如 [bash](#bash-工具)、[text editor](#文本编辑器)、[memory](#记忆工具)），您可以选择使用 [middleware](/langchain/oss/python/integrations/middleware/anthropic)，它们提供生产就绪的实现，包含内置的执行、状态管理和安全策略。

    当您需要一个即插即用的解决方案时，请使用中间件；当您需要自定义执行逻辑或直接使用 @[`bind_tools`][ChatAnthropic.bind_tools] 时，请使用工具（下文有详细说明）。
</Info>

<Note>
    **Beta 工具**

    如果将 Beta 工具绑定到您的聊天模型，LangChain 将会自动为您添加所需的 Beta 头部信息。
</Note>

### Bash 工具

Claude 支持一个客户端的 [bash 工具](https://platform.claude.com/docs/en/agents-and-tools/tool-use/bash-tool)，允许它在持久的 bash 会话中执行 shell 命令。这使其能够进行系统操作、脚本执行和命令行自动化。

<Note>
    **重要提示：你必须提供执行环境**

    LangChain 处理 API 集成（发送/接收工具调用），但 **你负责**：

    - 设置沙盒化的计算环境（Docker、VM 等）
    - 实现命令执行和输出捕获
    - 在智能体循环中将结果传回 Claude

    请参阅 [Claude bash 工具文档](https://platform.claude.com/docs/en/agents-and-tools/tool-use/bash-tool) 获取实现指南。
</Note>

<Info>
    **要求：**

    - Claude 4 模型或 Claude Sonnet 3.7
</Info>

        ```python expandable
        import subprocess

        from anthropic.types.beta import BetaToolBash20250124Param  # [!code highlight]
        from langchain_anthropic import ChatAnthropic

                    text=True,

            # Execute each tool call

                tool_messages.append(result)
        ```

### 工具搜索

Claude 支持服务器端的 [工具搜索](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool) 功能，能够实现动态工具发现和加载。Claude 不需要将所有工具定义提前加载到上下文窗口中，而是可以搜索您的工具目录并仅加载所需的工具。

这在以下情况下很有用：

- 您的系统中有 10+ 个工具
- 工具定义消耗了大量的 Token
- 您在使用大型工具集时遇到工具选择准确性问题

有两种工具搜索变体：

- **正则表达式** (`tool_search_tool_regex_20251119`)：Claude 构建正则表达式来搜索工具
- **BM25** (`tool_search_tool_bm25_20251119`)：Claude 使用自然语言查询来搜索工具

使用 `extras` 参数来指定 `defer_loading` 在 LangChain 工具上：
