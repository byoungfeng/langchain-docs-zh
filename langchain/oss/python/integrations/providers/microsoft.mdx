本页面涵盖了与 [Microsoft Azure](https://portal.azure.com) 及其他 [Microsoft](https://www.microsoft.com) 产品的所有 LangChain 集成。

<Tip>
    **推荐：Microsoft Foundry**

    对于以 [Microsoft Foundry](https://learn.microsoft.com/en-us/azure/foundry/) 为中心的新的 LangChain 或 LangGraph 应用，请从 [`langchain-azure-ai`](/langchain/oss/python/integrations/providers/azure_ai) 开始。它添加了 Foundry 项目端点、Azure 凭证集成、智能体服务、托管、工具、内容安全、检索和 Azure 可观察性。

    对于直接访问 [Azure OpenAI v1 API](https://learn.microsoft.com/en-us/azure/ai-foundry/openai/api-version-lifecycle?tabs=python) 模型，代码在 OpenAI 和 Azure 之间切换、传统 Azure OpenAI API 版本、完成式 LLM 或更小的依赖表面，请使用 `langchain-openai` 包。

    Foundry 资源包括 Azure OpenAI 功能，并增加了更广泛的模型目录、智能体服务和评估功能。如果您使用 Azure OpenAI 资源，[将其升级为 Foundry 资源](https://learn.microsoft.com/en-us/azure/foundry/how-to/upgrade-azure-openai) 以保留现有的 API 端点、状态和安全配置，同时获得 Foundry 功能的访问权限。

    对于智能体托管，请使用 [Microsoft Foundry 托管的智能体](#微软工厂托管智能体) 在具有内置运行时、会话、扩展、身份和协议端点的托管智能体平台上部署自定义 LangGraph 代码。

    **示例和教程：**
    - [microsoft-foundry/foundry-samples LangGraph 托管的智能体示例](https://github.com/microsoft-foundry/foundry-samples/tree/main/samples/python/hosted-agents/langgraph)：在本地运行 LangGraph 智能体或将它们部署到 Microsoft Foundry，包含响应、调用和 A2A 示例。
    - [Azure-Samples/langchain-azure-openai-starter](https://github.com/Azure-Samples/langchain-azure-openai-starter)：从生产就绪的 LangChain 和 Azure OpenAI 应用模板开始，允许您使用单个 `azd` 命令直接部署到 Azure。
    - [microsoft/langchain-for-beginners](https://github.com/microsoft/langchain-for-beginners)：一个动手课程，介绍使用 Azure OpenAI 的 LangChain。
    - [Azure-Samples/langchain-agent-python](https://github.com/Azure-Samples/langchain-agent-python)：在 Azure 上构建和部署 LangChain 智能体。
</Tip>

<Note>
    **Azure 上的 Claude**

    Microsoft Foundry 还提供对所有 [Anthropic Claude 模型](https://learn.microsoft.com/en-us/azure/foundry/foundry-models/how-to/use-foundry-models-claude) 的访问，包括 Opus、Sonnet 和 Haiku。Claude 模型通过专用的 Anthropic 原生端点提供服务，而不是 Azure OpenAI v1 API。使用 [`langchain-anthropic`](/langchain/oss/python/integrations/chat/anthropic) 指向您的 Foundry Anthropic 端点。
</Note>

## 选择包

`langchain-azure-ai` 和 @[`langchain-openai`] 是互补而非替代品。`langchain-azure-ai` 依赖于 `langchain-openai`，其聊天和嵌入类从 @[`ChatOpenAI`] 和 @[`OpenAIEmbeddings`] 继承，因此安装 Azure 包不会从您的依赖链中移除 OpenAI 包。

使用以下表格选择起点：

| 场景 | 包 |
| --- | --- |
| 以 Foundry 项目为中心的新应用 | `langchain-azure-ai` |
| Foundry 智能体服务、托管的 LangGraph、工具箱、内容安全、Azure 工具或 Application Insights | `langchain-azure-ai` |
| 从 Foundry 项目端点配置的嵌入 | `langchain-azure-ai` |
| 直接 Azure OpenAI v1 聊天调用 | `langchain-openai` |
| 相同代码必须在 OpenAI 和 Azure 之间切换 | `langchain-openai` |
| 现有的 @[`AzureChatOpenAI`] 应用 | `langchain-openai` |
| 传统日期的 Azure OpenAI API 版本 | `langchain-openai` |
| 完成式 LLM 接口 | `langchain-openai` |
| 最小的依赖和操作表面 | `langchain-openai` |

将现有的 `langchain-openai` 应用迁移到 `langchain-azure-ai` 不是一个即插即用的导入更改：

- 配置不同。`azure_endpoint`、`azure_deployment`、`api_version` 和 token-provider 参数变为 `project_endpoint` 或 `endpoint`、`model` 和 `credential`。
- 默认行为不同。`AzureAIOpenAIApiChatModel` 在解析项目端点时默认为响应 API。设置 `use_responses_api=False` 以保持聊天补全行为。
- `langchain-azure-ai` 中不存在 @[`AzureOpenAI`] 的完成式 LLM 对等物。
- @[`AzureChatOpenAI`] 携带 Azure 特定的响应元数据和内容过滤处理，Foundry 聊天模型不会重现。
- 两个包都遵循官方 OpenAI 架构，因此由 DeepSeek 或 Mistral 等兼容提供者返回的非标准字段可能不会被保留。

## 聊天模型

Microsoft 通过 Azure 提供三种主要选项来访问聊天模型：

1. **Microsoft Foundry**（推荐用于以项目为中心的应用）：使用 `AzureAIOpenAIApiChatModel` 从 `langchain-azure-ai`，并使用 Foundry 项目端点和 Azure 凭证。此包还与 Foundry 智能体、托管、工具、内容安全、检索和可观察性集成。
2. **[Azure OpenAI](https://learn.microsoft.com/en-us/azure/ai-services/openai/)**：使用 `ChatOpenAI` 从 `langchain-openai` 进行直接 v1 API 调用或切换 OpenAI 和 Azure 的代码。使用 `AzureChatOpenAI` 用于传统 Azure OpenAI API 版本和现有应用。
3. **[Azure ML](https://learn.microsoft.com/en-us/azure/machine-learning/)**：允许使用 Azure 机器学习部署和管理自定义或微调的开源模型。

### Microsoft Foundry

Microsoft Foundry 提供项目级别的模型和 Azure 服务访问。当您的应用使用 Foundry 项目、Azure 凭证或其他 Foundry 功能时，请使用 `AzureAIOpenAIApiChatModel` 从 `langchain-azure-ai`。

<CodeGroup>
    ```bash pip
    pip install -U langchain-azure-ai
    ```

    ```bash uv
    uv add langchain-azure-ai
    ```
</CodeGroup>

设置您的项目端点：

```bash
export AZURE_AI_PROJECT_ENDPOINT="https://<resource>.services.ai.azure.com/api/projects/<project>"
```

然后创建聊天模型：

```python
from azure.identity import DefaultAzureCredential
from langchain_azure_ai.chat_models import AzureAIOpenAIApiChatModel

llm = AzureAIOpenAIApiChatModel(
    model="gpt-5.2",  # your Foundry model deployment name
    credential=DefaultAzureCredential(),
)
```

有关完整设置指南，请参阅 [Microsoft Foundry 聊天模型集成](/langchain/oss/python/integrations/chat/azure_ai)。

#### 响应 API

Azure OpenAI 支持 [响应 API](https://learn.microsoft.com/en-us/azure/ai-foundry/openai/how-to/responses)，该 API 提供有状态对话、内置工具（网络搜索、文件搜索、代码解释器）和结构化推理摘要。 `ChatOpenAI` 在你设置 `reasoning` 参数时自动路由到响应 API，或者你可以使用 `use_responses_api=True` 显式启用：

<Tabs>
    <Tab title="Entra ID (recommended)">
        ```python
        from azure.identity import DefaultAzureCredential, get_bearer_token_provider
        from langchain_openai import ChatOpenAI

        token_provider = get_bearer_token_provider(
            DefaultAzureCredential(),
            "https://cognitiveservices.azure.com/.default",
        )

        llm = ChatOpenAI(
            model="gpt-5.4-mini",
            base_url="https://YOUR-RESOURCE-NAME.openai.azure.com/openai/v1/",
            api_key=token_provider,
            use_responses_api=True,
        )

        response = llm.invoke("Summarize the bitter lesson.")
        print(response.text)
        ```
    </Tab>

## 文档加载器

### Azure Blob 存储

>[Azure Blob 存储](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction) 是微软的云对象存储解决方案。Blob 存储针对存储海量非结构化数据进行了优化。非结构化数据是指不遵循特定数据模型或定义的数据，例如文本或二进制数据。

`Azure Blob Storage` 设计用于：
- 直接将图像或文档提供给浏览器。
- 存储用于分布式访问的文件。
- 流式传输视频和音频。
- 写入日志文件。
- 存储用于备份和恢复、灾难恢复和归档的数据。
- 存储用于本地或 Azure 托管的服务的分析的数据。

## 后端

### Azure Blob 存储后端

>[Azure Blob 存储](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction) 是微软的云对象存储解决方案。`AzureBlobBackend` 实现了 Deep Agents `BackendProtocol`，因此深度智能体可以将其整个工作区（文件、记忆和工件）持久化到 blob 容器中。

<Note>
`AzureBlobBackend` 是 `langchain-azure-storage` 包的一部分，该包目前处于 **公共预览** 状态。
</Note>

使用 `deepagents` 扩展进行安装（需要 Python 3.11+）：

<CodeGroup>
    ```bash pip
    pip install -U "langchain-azure-storage[deepagents]"
    ```

    ```bash uv
    uv add "langchain-azure-storage[deepagents]"
    ```
</CodeGroup>

```python
from langchain_azure_storage.deepagents import AzureBlobBackend
```

**快速入门：**

```python
from deepagents import create_deep_agent
from langchain_azure_storage.deepagents import AzureBlobBackend

backend = AzureBlobBackend(
    account_url="https://<my-storage-account-name>.blob.core.windows.net",
    container_name="agent-workspace",
    prefix="session-001/",  # Optional: isolate each agent/session under a prefix.
)

agent = create_deep_agent(backend=backend)

result = agent.invoke(
    {"messages": [{"role": "user", "content": "Write a hello world script to hello.py"}]}
)
```

后端默认为 [`DefaultAzureCredential`](https://learn.microsoft.com/en-us/azure/developer/python/sdk/authentication/credential-chains?tabs=dac#defaultazurecredential-overview)，并接受 `credential` 覆盖。

有关更多信息，请参见 [后端集成](/langchain/oss/integrations/backends)。有关完整使用细节和安全指南，请参见 [包存储库](https://github.com/langchain-ai/langchain-azure/tree/main/libs/azure-storage)。

from langchain_azure_cosmosdb import CosmosDBChatMessageHistory

history = CosmosDBChatMessageHistory(

### Azure cosmos DB 语义缓存

>[`AzureCosmosDBNoSqlSemanticCache`](https://github.com/langchain-ai/langchain-azure/tree/main/libs/azure-cosmosdb) 在 Azure Cosmos DB 中缓存 LLM 响应以 NoSQL 使用向量相似性，当再次看到语义相似的提示词时返回缓存的结果。

<CodeGroup>
    ```bash pip
    pip install langchain-azure-cosmosdb
    ```

    ```bash uv
    uv add langchain-azure-cosmosdb
    ```
</CodeGroup>

```python
from azure.cosmos import CosmosClient, PartitionKey
from langchain_core.globals import set_llm_cache
from langchain_azure_cosmosdb import AzureCosmosDBNoSqlSemanticCache

cosmos_client = CosmosClient("<endpoint>", "<key>")

cache = AzureCosmosDBNoSqlSemanticCache(
    cosmos_client=cosmos_client,
    embedding=embedding,
    vector_embedding_policy=vector_embedding_policy,
    indexing_policy=indexing_policy,
    cosmos_container_properties={"partition_key": PartitionKey(path="/id")},
    cosmos_database_properties={"id": "cache-db"},
    vector_search_fields={"text_field": "text", "embedding_field": "embedding"},
    database_name="cache-db",
    container_name="cache-container",
)

set_llm_cache(cache)
```

对于异步使用，导入 `AsyncAzureCosmosDBNoSqlSemanticCache`。

## 向量存储

### Azure cosmos DB
AI 智能体可以依赖 Azure Cosmos DB 作为统一的 [记忆系统](https://learn.microsoft.com/en-us/azure/cosmos-db/ai-agents#ai-agent-memory-system) 解决方案，享受速度、规模和简单性。该服务成功 [使 OpenAI 的 ChatGPT 服务](https://www.youtube.com/watch?v=6IIUtEFKJec&t) 能够以高可靠性和低维护成本动态扩展。由 atom-record-sequence 引擎驱动，它是世界上第一个提供无服务器模式的 [NoSQL](https://learn.microsoft.com/en-us/azure/cosmos-db/distributed-nosql)、[关系型](https://learn.microsoft.com/en-us/azure/cosmos-db/distributed-relational) 和 [向量数据库](https://learn.microsoft.com/en-us/azure/cosmos-db/vector-database) 服务。

以下是两个可用的 Azure Cosmos DB API，它们可以提供向量存储功能。

#### Azure cosmos DB for MongoDB (vCore)

>[Azure Cosmos DB for MongoDB vCore](https://learn.microsoft.com/en-us/azure/documentdb/) 使创建具有完整原生 MongoDB 支持的数据库变得轻松。
> 您可以通过将应用程序指向 MongoDB vCore 账户的连接字符串来应用您的 MongoDB 经验，并继续使用您喜欢的 MongoDB 驱动程序、SDK 和工具。

## 运行时

### 微软工厂托管智能体

[微软工厂托管智能体](https://learn.microsoft.com/en-us/azure/foundry/how-to/develop/langchain-hosted-agents)在一个托管运行时中运行自定义 LangGraph 代码。使用 `langchain_azure_ai.agents.hosting` 包来暴露编译后的 LangGraph 图，同时由工厂管理运行时、会话、扩展、身份和协议端点。

<Note>
    LangGraph 托管支持需要 `langchain-azure-ai[hosting]>=1.2.8`。
</Note>

开始之前，您需要一个 Azure 订阅、一个工厂项目、一个部署的对话模型、Python 3.10 或更高版本，以及 Azure CLI 身份验证。部署智能体还需要在项目上具有工厂项目管理员角色。

根据客户端如何与智能体交互，选择托管协议：

| 协议 | 运行参数 | SDK 主机类 | 端点 | 使用场景 |
| --- | --- | --- | --- | --- |
| 响应 | `--protocol responses` | `ResponsesHostServer` | `/responses` | 您需要兼容 OpenAI 的聊天、流式输出、响应历史记录或对话线程。大多数对话智能体从这里开始。 |
| 调用 | `--protocol invocations` | `InvocationsHostServer` | `/invocations` | 您需要一个自定义的 JSON 形状、一个 webhook 风格的端点或非对话处理。 |

<Note>
    对于使用基于 `BaseChatOpenAI` 模型的响应 API 的托管图，使用 `output_version="responses/v1"`。在 `langchain-openai` 1.0.0 或更高版本中，您可以省略此设置，除非被 `LC_OUTPUT_VERSION` 覆盖。此指导适用于响应和调用托管协议。
</Note>

查看 [响应协议](https://github.com/microsoft-foundry/foundry-samples/tree/main/samples/python/hosted-agents/langgraph/responses/10-run) 和 [调用协议](https://github.com/microsoft-foundry/foundry-samples/tree/main/samples/python/hosted-agents/langgraph/invocations/03-run) 的完整运行示例。
