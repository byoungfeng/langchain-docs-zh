:::python

:::

将中间件传递给 `middleware` 的 `createDeepAgent` 参数。每个实例通过其 `.name` 被合并到 [Deep Agents stack](#deep-agents-堆栈) 中。名称与内置条目匹配的实例会替换该条目。其他内容则插入到 @[`PatchToolCallsMiddleware`] 之后。

3. @[`SummarizationMiddleware`]
4. @[`PatchToolCallsMiddleware`]
5. **提示词缓存**中间件（始终注册；对不支持的模型，每个条目不执行操作）
6. **Harness profile 附加功能**和**排除工具过滤**，如果解析的模型配置定义了它们
:::

1. @[`FilesystemMiddleware`]
2. @[`SubAgentMiddleware`]（[因为通用子智能体](/langchain/oss/deepagents/subagents#默认子智能体)会自动添加，除非 harness profile 禁用它）

7. @[`UnsupportedContentMiddleware`]

#### 全栈

从第一到最后一层：

:::python

1. @[`FilesystemMiddleware`]: 处理文件系统操作，如读取、写入和导航目录。当你传递 `permissions` 时，这里包含文件系统权限强制执行，以便它可以评估智能体可能调用的每个工具。
2. @[`SubAgentMiddleware`]: 仅当至少有一个同步子智能体可用时。生成和协调子智能体以委托任务。包含在 [裸栈](#裸栈模式) 中，因为通用子智能体默认自动添加；通过禁用该子智能体并传递无同步 `subagents` 来省略它。参见 [无子智能体运行](/langchain/oss/deepagents/subagents#不使用子智能体)。
3. @[`SummarizationMiddleware`]: 当对话变长时（通过 @[create_summarization_middleware]），将消息历史压缩以保持在上下文限制内。
4. @[`PatchToolCallsMiddleware`]: 在消息历史中修复悬空工具调用，当运行在中断后恢复或接收格式错误的工具调用参数时。在Anthropic提示缓存和下方的尾栈之前 **运行**。
5. @[`AsyncSubAgentMiddleware`]: 仅当你配置异步子智能体时。
6. **你的中间件参数**: 作为 `middleware` 参数传递的可选中间件在Patch之后但在堆栈其余部分之前合并。其 `.name` 与上面内置条目之一匹配的实例会替换该实例，而不是复制它；其他任何内容都会放在这里。参见 [覆盖默认中间件实例](#覆盖默认中间件实例)。
7. **利用配置文件附加**: 解析的模型配置文件提供的特定于提供者的中间件，如果有的话。
8. @[`SkillsMiddleware`]: 仅当你传递 `skills` 时。在您的中间件之后、提示缓存之前运行，因此它看到总结的对话和实际调用的模型。传递一个名为 `SkillsMiddleware` 的中间件会将其就地替换。
9. **提示缓存** (@[`AnthropicPromptCachingMiddleware`] 和 @[`BedrockPromptCachingMiddleware`]): 两者始终注册并在Patch之后以及您的中间件之后运行，以便缓存的prefix与实际发送到模型的匹配。它们在它们不支持的模型上执行no-ops (`unsupported_model_behavior="ignore"`)，因此Anthropic中间件适用于Anthropic模型，Bedrock中间件适用于具有缓存支持的AWS Bedrock模型。
10. @[`MemoryMiddleware`]: 仅当你传递 `memory` 时。

    <Note>
    `MemoryMiddleware` 放在 **profile extras** 和提示缓存中间件之后，因此注入记忆的更新不太可能使缓存prefix失效。在 `create_deep_agent` 实现注释中也提到了相同的排序问题。
    </Note>

11. `HumanInTheLoopMiddleware`: 仅当通过 `interrupt_on` 时。在配置的工具调用处暂停，等待人工批准或输入。
12. **排除工具过滤**: 当 harness profile 列出排除的工具时，中间件会从智能体中移除这些工具。

:::

:::js

2. @[`SubAgentMiddleware`]: 仅当至少有一个同步子智能体可用时。生成和协调子智能体以委托任务。包含在 [裸栈](#裸栈模式) 中，因为通用子智能体默认自动添加；通过禁用该子智能体并传递无同步 `subagents` 来省略它。参见 [无子智能体运行](/langchain/oss/deepagents/subagents#不使用子智能体)。
3. @[`SummarizationMiddleware`]: 当对话变长时，通过 @[createSummarizationMiddleware] 将消息历史压缩以保持在上下文限制内。
4. @[`PatchToolCallsMiddleware`]: 在运行中断后恢复或接收到格式错误的工具调用参数时，修复消息历史中的悬空工具调用。运行 **在** Anthropic 提示词缓存和下方的尾栈 **之前**。
5. @[`AsyncSubAgentMiddleware`]: 仅当您配置异步子智能体时。

7. **Harness profile 附加**: 从解析的模型 profile 中提供的特定于提供者的中间件，如果有的话。
8. @[`SkillsMiddleware`]: 仅当通过 `skills`，或通过 `createSkillsMiddleware` 实例传递到 `middleware`。无论如何，它都在您的中间件之后、提示词缓存之前运行，因此可以看到总结的对话和实际调用的模型。
9. **提示词缓存** (@[`AnthropicPromptCachingMiddleware`] 和 @[`BedrockPromptCachingMiddleware`]): 分别为 Anthropic 模型和 Amazon Bedrock Converse 模型自动添加。两者都在 Patch 之后和您的中间件之后运行，因此缓存的prefix与实际发送给模型的内容匹配。
10. @[`MemoryMiddleware`]: 仅当通过 `memory`。

    <Note>
    `MemoryMiddleware` 放置在 profile 附加和提示词缓存中间件 **之后**，因此注入的记忆更新不太可能使缓存前缀失效。在 `createDeepAgent` 实现评论中也提到了相同的排序问题。
    </Note>

11. `HumanInTheLoopMiddleware`: 仅当传递 `interruptOn` 时。在配置的工具调用处暂停，等待人工批准或输入。
12. **排除工具过滤**: 当 harness profile 列出排除的工具时，中间件会从智能体中移除这些工具。
13. @[`UnsupportedContentMiddleware`]: 使用文本占位符重写请求中的不支持的多元模态内容。

:::

### 同步子智能体栈

:::python

内置的 **通用** 子智能体和每个声明式的同步 `SubAgent` 图使用一个栈，`create_deep_agent` 在代码中构建。它在大致形状上与主智能体匹配（文件系统、摘要、Patch、配置文件额外信息、技能、Anthropic 和 Bedrock 缓存、可选权限），但子智能体图中 **没有** @[`SubAgentMiddleware`]（只有父智能体暴露 `task` 工具）。

当声明式子智能体设置 `interrupt_on` 时，该值会被转发到 `create_agent` 以供子智能体使用，这会为配置的工具调用设置人工参与处理。

:::

### 覆盖默认中间件实例

:::python
<Note>
通过匹配 `.name` 来覆盖默认中间件需要 `deepagents>=0.7`。
</Note>

将一个中间件实例传递给 `.name`，使其匹配 [深度智能体堆栈](#deep-agents-堆栈) 中的条目，例如 @[`SummarizationMiddleware`]，以替换该内置实例，而不是追加一个副本。任何你传递的中间件实例，其 `.name` **不**匹配内置条目，都不会被替换，它位于最后一个核心中间件条目之后，以及配置文件、提示词缓存和记忆之前。参见 [完整堆栈](#全栈) 了解完整顺序。

```python
from deepagents import create_deep_agent
from deepagents.backends import StateBackend
from deepagents.middleware import SummarizationMiddleware

backend = StateBackend()
model = "openai:gpt-5.5"

custom_summarization = SummarizationMiddleware(
    model=model,
    backend=backend,
    summary_prompt="Your custom summary prompt here.",
)

agent = create_deep_agent(
    model=model,
    middleware=[custom_summarization],  # replaces the default SummarizationMiddleware
)
```

<Note>
覆盖 **替换** 默认中间件实例，而不是与其合并。这意味着你的替换必须配置所有它需要的设置。这对于 `FilesystemMiddleware` 特别重要：如果你覆盖它，你必须将 `backend`（如果适用，则为 `permissions`）直接传递给你的自定义实例，因为它不会继承传递给 `create_deep_agent()` 的 `backend=` 和 `permissions=`。要限制可用的文件系统工具，请将 `tools` 允许列表传递给你的自定义 @[`FilesystemMiddleware`] 实例；参见 [虚拟文件系统访问](/langchain/oss/deepagents/overview#虚拟文件系统访问) 的“限制文件系统工具”示例。

</Note>

通用子智能体（深度智能体会自动添加），会从主智能体继承默认中间件的覆盖，而不会传递主智能体特有的中间件。

通过 `subagents=` 定义的声明式子智能体不会继承主智能体的中间件定制。将覆盖直接传递到该子智能体自己的 [`middleware`](/langchain/oss/deepagents/subagents#子智能体（基于字典）) 字段中以应用；该字段与 `middleware=` [相同的方式匹配于同步子智能体栈](#同步子智能体栈)。

        ```python

        from deepagents.backends import StateBackend

                    model=model,
        ```
