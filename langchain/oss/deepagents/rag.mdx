基于 LLM 的最强大的应用之一是复杂的问答（Q&A）聊天机器人，它通过向 LLM 提供推理时访问数据集的方式增强 LLM。
这可能涉及私有数据、最新数据，或不是 LLM 训练数据集一部分的数据。
这些应用使用一种称为检索增强生成（Retrieval Augmented Generation，简称 RAG 的技术。

:::python
[Deep Agents](/langchain/oss/deepagents/overview) 为 RAG 提供了基础组件：自定义检索工具、[文件系统后端](/langchain/oss/deepagents/backends)、[子智能体](/langchain/oss/deepagents/subagents)、[技能](/langchain/oss/deepagents/skills) 和 [评分标准](/langchain/oss/deepagents/rubric)。你可以根据语料库大小、延迟需求和答案必须严格基于源数据的程度，以不同的方式组合它们。
:::

本指南介绍了多种 RAG 模式，并通过一个端到端示例进行说明：一个文档问答智能体，它索引 [docs.langchain.com](https://docs.langchain.com) 的一个子集，在查询时检索相关片段，将它们卸载到文件系统，并将分析委托给子智能体，以便协调器上下文保持清晰。

## RAG 模式

Deep Agents 允许你以多种方式编排检索、分析和综合：

- **技能引导检索**：用户提出问题。智能体加载一个描述如何搜索你语料库的相关技能（使用哪个索引、查询格式化、引用格式）。智能体按照该指导调用你的检索工具，然后综合答案。
- **评分标准检查的依据**：用户提出问题。智能体检索证据并起草答案。一个配置了 `RubricMiddleware` 的评分标准子智能体评估响应是否基于检索的源材料。智能体会修改，直到评分标准通过或达到迭代上限。
- **任务驱动调查**：用户提出问题。如果你 [选择参与任务规划](/langchain/oss/deepagents/overview#任务规划)，智能体将使用规划工具创建一个待办事项列表，包括要调查的文档页面或搜索查询。它检索每个项目的结果，然后从收集的证据中综合答案。
- **检索、卸载和委托**：用户提出问题。智能体检索匹配的片段并将它们写入文件系统后端，而不是在协调器上下文中保留完整文本。子智能体并行读取、搜索和总结单个文件。对于大文档，智能体可以使用内置搜索工具翻页浏览文件，或运行 [代码解释器](/langchain/oss/deepagents/code/overview) 从源数据生成表格、时间线或可视化内容。

:::python
<Note>
评分标准需要 `deepagents>=0.6.5`，目前处于 [测试阶段](https://docs.langchain.com/langsmith/release-stages)。
</Note>
:::

本教程实现了 **检索、卸载和委托** 模式。其他模式中也出现了相同的原语：技能通常包装检索工作流，评分标准可以对这些流程进行评分，而选择性的待办事项规划有助于将复杂问题分解为专注的搜索。

## 检索的重要性

语言模型本身无法访问您的文档。如果您向它询问最近更改的特定 API，它将根据训练数据回答：通常合理，有时错误，并且从未基于您的真实来源。

即使文档可用，您通常也无法将所有内容都放入上下文窗口中。因此，您必须仅选择与给定问题相关的段落，而本身就是一个非平凡的任务。

### 您将构建的内容

1. **索引**：将 LangChain 文档加载到向量存储中。
2. **搜索**：构建一个自定义工具，运行向量相似度搜索并将每个检索到的片段写入智能体文件系统。
3. **分析**：将文件分析委托给一个子智能体，该智能体读取文件并返回专注的摘要。
4. **合成**：使用主智能体从子智能体报告中获取最终答案。

## LangChain 文档索引指南

在索引步骤中，您将把源内容转换为 _片段_ 的数值表示。这种数值表示捕捉了片段的语义意义。将这些数值表示及其对应的文档片段存储在一个 `VectorStore` 中，可以在用户基于其自身的数值表示发送查询时，帮助您高效地检索相关内容。

索引通常包含四个步骤：

1. **[加载](#加载文档)**: 将您的数据源加载到 @[`Document`] 对象中。
2. **[分割](#分割文档)**: 使用 [文本分割器](/langchain/oss/integrations/splitters) 将大型 `Document` 分割成更小的片段。这对于索引数据和将其传递给模型都很有用，因为大型片段更难进行搜索，要么无法适应模型有限的上下文窗口，要么会使用不必要的 Token。
3. **[嵌入](#选择嵌入模型)**: [嵌入](/langchain/oss/python/integrations/embeddings) 模型将每个片段转换为一个数值向量，该向量捕捉其含义，从而能够在您的内容中进行相似性搜索。
4. **[存储](#将块和嵌入存储在向量存储中)**: 使用一个 [向量存储](/langchain/oss/python/integrations/vectorstores) 来索引片段及其嵌入，以便进行检索。

![index_diagram](/images/rag_indexing.png)

在索引步骤中，获取文档页面，将它们分割成片段，嵌入这些片段，并将它们存储在一个 `VectorStore` 中。智能体在运行时搜索此索引；它不会在每次提问时重新获取整个网站。

### 分割文档

加载的文档很长，总共有超过 100k 个 Token，这使得它太大而无法适应许多模型的上下文窗口。
对于那些能够将完整语料库放入其上下文窗口的模型，模型也可能难以在非常长的输入中找到信息。使用上下文窗口处理大量内容也不是 Token 高效的。

为了方便使用，将 @[`Document`] 对象分割成片段。这些片段将用于后续步骤中的嵌入和向量存储。

使用 `RecursiveCharacterTextSplitter` 递归地分割文档，使用常见的分隔符（如换行符），直到每个片段达到适当的大小。
`RecursiveCharacterTextSplitter` 是推荐的 `TextSplitter`，适用于通用文本用例。

```python expandable wrap
RAG_WORKFLOW_INSTRUCTIONS = """# Documentation Q&A workflow

Answer questions about LangChain using the indexed documentation corpus.

1. **Plan**: Break complex questions into focused search queries.
2. **Search**: Call search_documentation with a query. The tool saves matching chunks under /retrieved/ and returns file paths.
3. **Analyze**: Delegate each chunk file to the chunk-analyst subagent with task(). Include the user question and one file path per task. Launch multiple task() calls in parallel when you retrieved several chunks.
```

## 安全注意事项

<Warning>
RAG 应用程序容易受到 **间接提示词注入** 的影响。检索到的文档可能包含类似于指令的文本。由于检索到的块与您的系统提示词共享上下文窗口，模型可能会遵循文档中嵌入的指令，而不是您的预期提示词。
</Warning>

没有提示词或分隔符策略可以完全防止间接提示词注入。本教程中的协调器和子智能体提示词要求模型将检索到的内容视为数据，并且搜索工具在块前添加一个 `# Source:` 标头，以便分析师可以将元数据与正文内容区分开来。这些模式在某些情况下可能有所帮助，但它们不能提供可靠的防护。

在将智能体输出呈现给用户之前进行验证。检查答案是否引用了预期的文档路径，并且断言是否与检索到的源材料一致。

有关更多内容，请参阅关于 [提示词注入](https://simonwillison.net/series/prompt-injection/) 的研究。
