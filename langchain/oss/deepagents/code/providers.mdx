Deep Agents Code 支持任何与 LangChain 兼容的 [聊天模型提供方](/langchain/oss/python/integrations/chat)，解锁对几乎所有支持工具调用的 LLM 的使用。任何提供 OpenAI 兼容或 Anthropic 兼容 API 的服务也可以开箱即用——请参阅 [兼容的 API](/langchain/oss/deepagents/code/config-file#兼容的-api)。

## 快速入门

Deep Agents Code 自动集成到以下 [模型提供方](#提供方参考) 中：无需除安装相关提供方包之外的额外配置。

1. **安装提供方包**

    每个模型提供方都需要其对应的 LangChain 集成包。这些作为可选扩展包提供，以保持应用程序轻量。OpenAI、Anthropic 和 Gemini 默认包含在内。在 `/install` 中会话内或从 shell 中使用 `dcode --install` 安装任何其他扩展包：

    <CodeGroup>
        ```txt In session
        /install groq
        ```

        ```bash Shell
        dcode --install groq
        ```
    </CodeGroup>

    使用不带参数的 `/install` 列出有效的扩展包。在初始 CLI 安装期间预安装扩展包，请设置 `DEEPAGENTS_CODE_EXTRAS`：

    ```bash
    curl -LsSf https://langch.in/dcode | DEEPAGENTS_CODE_EXTRAS="baseten,groq" bash
    ```

2. **设置凭证**

    使用 [`/auth`](/langchain/oss/deepagents/code/credentials#使用-/auth（推荐）) 凭证管理器添加您的提供方 API 密钥：

    ```txt
    /auth
    ```

    `/auth` 显示可用提供方的列表并存储跨会话重用的凭证。

    对于非交互式运行、CI/CD 或任何 TUI 不可用的地方，使用 [`dcode auth set`](/langchain/oss/deepagents/code/credentials#从-shell-管理凭据（dcode-auth）) 或设置提供方的环境变量来存储相同的密钥。有关完整的密钥解析顺序、[`DEEPAGENTS_CODE_` 前缀](/langchain/oss/deepagents/code/configuration#deepagents_code_-前缀)（将密钥限定于 Deep Agents Code）以及每个提供方的环境变量的 [提供方参考](#提供方参考)，请参阅 [提供方凭证](/langchain/oss/deepagents/code/credentials)。

    要配置模型参数，请参阅 [模型参数](#模型参数)。

### 使用 ChatGPT 登录

`openai_codex` 提供方允许您使用付费 **ChatGPT** 订阅的 OpenAI 的 Codex 模型，而不是 `OPENAI_API_KEY`。您使用 ChatGPT 账户登录，并在 `/auth` 和 `/model` 切换器中显示为其自己的提供方，与基于 API 密钥的 `openai` 提供方分开。

<Steps>
    <Step title="Start the sign-in">
        在任何会话中运行 `/auth` 并选择 **`openai_codex`**。由于 ChatGPT 通过浏览器进行登录，因此这将启动浏览器登录而不是请求 API 密钥。
    </Step>

    <Step title="Authorize in your browser">
        Deep Agents Code 会打开浏览器至 ChatGPT 登录页面。如果无法打开浏览器（例如通过 SSH），它也会在屏幕上显示登录 URL，以便您将其复制到另一台设备的浏览器中。
    </Step>

    <Step title="Select a Codex model">
        登录后，Codex 模型将出现在 `/model` 切换器下的 `openai_codex` 提供商下。直接使用其规范切换到其中一个：

        ```txt
        /model openai_codex:gpt-5.5
        ```
    </Step>
</Steps>

您的登录状态会在会话之间持续。要检查您的状态或登出，请运行 `/auth`，选择 `openai_codex`，并选择重新认证或登出。

<Note>
    `openai_codex` 与 `openai` 是分开的。要使用标准 API 密钥使用 OpenAI 模型，请使用常规 `openai` 提供商（例如 `/model openai:gpt-5.5`）。
</Note>

<Note>
    某些特定于提供者的账户类型或密钥范围可能无法用于 API 访问。如果某个提供者在 `/auth` 中配置了，但请求仍然失败，请验证账户计划和 API 密钥权限是否与提供者的 API 要求匹配。
</Note>

## 切换模型

要在 Deep Agents Code 中切换模型，可以：

1. **使用交互式模型切换器** 并使用 `/model` 命令。

    <Note>
        这里不会显示所有模型。如果您的模型缺失，请直接传递模型名称（例如 `/model gpt-5.5`），或将其添加到 `config.toml`。
    </Note>
2. **直接指定模型名称** 作为参数，例如 `/model gpt-5.5`。您可以使用任何受所选提供者支持的模型，无论它是否出现在选项 1 的列表中。模型名称将被传递给 API 请求。
3. **在启动时指定模型** 通过 `--model`，例如：

    ```txt
    dcode --model openai:gpt-5.5
    ```

<Accordion title="Model resolution order" icon="list-numbers">
    当 Deep Agents Code 启动时，它会按以下顺序确定要使用的模型：

    1. **`--model` 标志** 如果提供，总是优先。
    2. **`[models].default`** 在 `~/.deepagents/config.toml` 中——用户的意向长期偏好。
    3. **`[models].recent`** 在 `~/.deepagents/config.toml` 中——通过 `/model` 切换到的最后一个模型。自动写入；永远不会覆盖 `[models].default`。
    4. **环境自动检测**：回退到第一个可用的启动凭证，按顺序检查：`OPENAI_API_KEY`、`ANTHROPIC_API_KEY`、`GOOGLE_API_KEY`、`GOOGLE_CLOUD_PROJECT` (Gemini 企业代理平台)。

    这个启动回退有意仅检查这四个凭证。其他支持的提供者（例如 Groq）仍然可以通过 `--model`、`/model` 和保存的默认值（`[models].default` / `[models].recent`）访问。
</Accordion>

### 切换器中显示哪些模型

`/model` 选择器动态构建其列表来自已安装的提供者包。展开下方以获取完整标准和故障排除。

<Accordion title="How the switcher builds its model list" icon="list-search">
    交互式 `/model` 选择器从已安装的提供者包和 `config.toml` 中配置的模型构建其列表。

    当满足以下条件时，模型会显示：

    1. 提供者包已安装。
    2. 模型来自提供者包、本地提供者或您的 `config.toml`。
    3. 模型配置文件未将文本输入或输出标记为不支持。

    如果模型缺失，请直接使用 `/model <provider>:<model>` 或将其添加到 [`[models.providers.<name>].models`](/langchain/oss/deepagents/code/config-file#adding-models-to-the-interactive-switcher)。

    <Tip>
        凭证状态**不会**影响模型是否列出。即使凭证缺失，您仍然可以选择该模型。提供者在请求时报告身份验证错误。
    </Tip>
</Accordion>

    <CodeGroup>

### 设置默认模型

您可以设置一个持久化的默认模型，该模型将应用于所有未来的 CLI 启动：

* **通过模型选择器：** 打开 `/model`，导航到所需的模型，并按 `Ctrl+S` 将其固定为默认值。再次按 `Ctrl+S` 将当前默认值清除。
* **通过命令：** `/model --default provider:model` (例如，`/model --default anthropic:claude-opus-4-8`)
* **通过配置文件：** 在 `~/.deepagents/config.toml` 中设置 `[models].default` (参见 [配置](/langchain/oss/deepagents/code/configuration))。
* **从 Shell：**

    ```bash
    dcode --default-model anthropic:claude-opus-4-8
    ```

要查看当前默认值：

```bash
dcode --default-model
```

要清除默认值：

* **从 Shell：**

    ```bash
    dcode --clear-default-model
    ```

* **通过命令：** `/model --default --clear`
* **通过模型选择器：** 在当前固定的默认模型上按 `Ctrl+S`。

如果没有默认值，Deep Agents Code 将使用最近使用的模型。

### 模型参数

将额外的构造函数 kwargs 传递给模型—采样控制、推理/思考预算、上下文窗口大小、请求超时以及底层聊天模型类接受的任何其他内容。有三个地方可以设置它们，按优先级排序（从高到低）：

1. **使用 `--model-params` 在启动时一次性设置。** JSON 字符串，仅会话有效：

    ```bash
    # OpenAI reasoning effort
    dcode --model openai:gpt-5.5 --model-params '{"reasoning": {"effort": "high"}}'

    # Anthropic extended thinking
    dcode --model anthropic:claude-opus-4-8 --model-params '{"thinking": {"type": "enabled", "budget_tokens": 10000}, "max_tokens": 16000}'
    ```

2. **使用 `/model --model-params` 在会话中设置。** 相同的 JSON 语法—无需重启即可交换参数（可选地交换模型）：

    ```txt
    /model --model-params '{"temperature": 0.7}' anthropic:claude-opus-4-8
    /model --model-params '{"num_ctx": 16384}'           # opens selector, applies params to choice
    ```

3. **在 `config.toml` 中持久设置。** 提供者级别的默认值（可选的每个模型子表），适用于每次启动：

    ```toml
    [models.providers.anthropic.params]
    thinking = { type = "enabled", budget_tokens = 10000 }
    max_tokens = 16000

    [models.providers.openai.params]
    reasoning = { effort = "high", summary = "auto" }
    output_version = "responses/v1"

    [models.providers.ollama.params]
    num_ctx = 16384
    temperature = 0

    # Per-model override—wins over provider-level keys
    [models.providers.ollama.params."qwen3:4b"]
    temperature = 0.5
    ```

CLI 标志覆盖配置文件 `params`，且仅会话有效（会话中的更改不会持久化）。`config.toml` 中的每个模型子表覆盖提供者级别的键（浅合并—参见 [模型构造函数参数](/langchain/oss/deepagents/code/config-file#模型构造函数参数) 获取完整语义）。`--model-params` 不能与 `--default` 结合使用。

对于重试次数，请优先使用 `--max-retries` 或顶层 [`[retries]` 配置](/langchain/oss/deepagents/code/config-file#retries)。

<Tip>
    任何底层聊天模型构造函数接受的 kwargs 都是有效的。有关完整列表，请参阅提供者的参考文档—例如 [`ChatAnthropic`](https://reference.langchain.com/python/langchain-anthropic/langchain_anthropic/chat_models/ChatAnthropic)、[`ChatOpenAI`](https://reference.langchain.com/python/langchain-openai/langchain_openai/chat_models/base/ChatOpenAI)、[`ChatOllama`](https://reference.langchain.com/python/langchain-ollama/langchain_ollama/chat_models/ChatOllama)。未知的 kwargs 将被转发到上游 API 请求，因此新发布的参数无需 CLI 更新即可生效。
</Tip>

<Note>
    不要将凭证 (`api_key`) 放在 `params` 中—改用 [`api_key_env`](/langchain/oss/deepagents/code/config-file#提供商配置) 指向环境变量。

</Note>

要覆盖模型的运行时 *配置* (`max_input_tokens`、`tool_calling`、能力标志)—与构造函数参数不同—请参阅 [配置覆盖](/langchain/oss/deepagents/code/config-file#配置文件覆盖（高级）)。
