:::python
[模型上下文协议（MCP）](https://modelcontextprotocol.io) 是一个开放协议，它标准化了应用程序如何为语言模型提供工具和上下文。LangChain 智能体通过 @[`MCPAdapter`] 调用 MCP 服务器上定义的工具，@[`MCPAdapter`] 发现服务器的工具，并将它们适配为 LangChain 工具，然后可以直接传递给 @[`create_agent`]。

@[`MCPAdapter`] 基于 [FastMCP](https://gofastmcp.com) 构建，FastMCP 处理传输推断、协议协商、连接管理和身份验证。本节涵盖 LangChain 特定层，并链接到 FastMCP 客户端文档以获取底层连接细节。

<Note>
`langchain.mcp` 命名空间需要 `langchain[mcp]>=1.4.0`，目前处于 Beta 版本。从它导入会在每个进程中触发一次 `LangChainBetaWarning`。API 可能会发生变化。

如果您在 v1.4.0 之前使用过 MCP，请参阅 [从 `langchain-mcp-adapters` 迁移](/langchain/oss/python/migrate/langchain-mcp-adapters)。
</Note>

## 传输

:::python

@[`MCPAdapter`] 从您提供的目标推断传输。目标是在进程服务器、本地脚本通过 stdio 和远程 URL 之间的唯一区别：

<McpTransportsPy />

目标可以是以下任何一项：

- **一个 `http`/`https` URL**（`str`）：通过 Streamable HTTP 访问。
- **一个脚本路径**（`Path`）：作为子进程通过 stdio 启动。
- **一个传输对象**（`StreamableTransport`）：预配置的传输对象。请参阅 [客户端传输](https://gofastmcp.com/clients/transports)。
- **一个进程内 `FastMCP` 服务器**：在内存中连接，无需子进程或套接字。
- **一个 `MCPConfig` 字典**（`{"mcpServers": {...}}`）：一个适配器背后的多个服务器。请参阅 [连接](/langchain/oss/langchain/mcp/connections#多个服务器)。
- **一个预构建的 `fastmcp.Client`**：用于对传输、[缓存](https://gofastmcp.com/clients/client#response-caching) 和 [协议协商](https://gofastmcp.com/clients/client#protocol-negotiation) 进行完全控制。

<Warning>
一个 `str` 目标必须是 `http` 或 `https` URL。FastMCP 通过将其作为文件系统路径进行测试来解析字符串，然后再将其作为 URL 进行测试，因此命名现有 `.py` 或 `.js` 文件的字符串将启动该文件作为子进程。由于字符串是配置或模型最常以何种形式接收的目标形式，@[`MCPAdapter`] 会拒绝不符合 URL 形状的字符串。
</Warning>

:::

:::js

@[`MCPAdapter`] 接受一个命名服务器定义的映射。它从每个定义中选择传输，因此一个适配器可以同时连接到本地 stdio 服务器和远程 HTTP 服务器：

<McpTransportsJs />

每个服务器定义可以使用以下传输之一：

- **stdio**：提供 `command` 和 `args`。适配器将命令作为子进程启动，并通过标准输入和输出进行通信。
- **Streamable HTTP**：提供 `url`。这是基于 URL 服务器的默认传输，因此 `transport: "http"` 是可选的。
- **SSE**：提供 `url` 并设置 `transport: "sse"`。仅用于暴露 SSE 端点的遗留服务器使用此传输。

传输选择和协议协商是分开的。可选的 `mode` 设置控制客户端接受哪个 MCP 协议时代。请参阅 [协议时代](/langchain/oss/langchain/mcp/connections#协议时代)。

<Note>
对于新的远程服务器，省略 `transport` 和 `mode`。适配器使用 Streamable HTTP 并自动进行协议协商。仅在连接到具有已知遗留要求的服务器时指定这些设置。
</Note>

:::
