## 工具执行期间的服务器请求

大多数工具在调用中途不需要向客户端请求任何信息。当服务器需要输入时，@[`MCPAdapter`] 会以 [ elicitation](https://modelcontextprotocol.io/specification/draft/client/elicitation) 的形式通过 LangGraph @[`interrupt`] 提示客户端。

### elicitation

[ elicitation](https://modelcontextprotocol.io/specification/draft/client/elicitation) 允许 MCP 服务器在工具调用期间请求输入。适配器使用 LangGraph 中断暂停运行。您的应用程序向用户展示请求，并使用他们的答案恢复运行。当通过 MCP 端点暴露的智能体暂停时，Agent Server 会以这种方式请求输入。更多详情，请参阅 [ Human-in-the-loop over MCP](https://docs.langchain.com/langsmith/server-mcp-elicitation)。

将 [ checkpointer](/langchain/oss/langchain/short-term-memory) 附加到智能体，并在调用和恢复时使用相同的 `thread_id`。

本示例假设预订工具请求一个日期并暂停一次。将示例日期替换为用户的答案。

:::python
<McpElicitationPy />

 elicitation 默认开启。适配器声明此功能并驱动中断循环。如果客户端已经包含自己的 elicitation 处理器，则不会覆盖而是尊重它。

使用 `Command(resume={"responses": {key: answer}})` 恢复。中断负载和答案类型位于 `langchain.mcp.elicitation`。
:::

:::js
基于中断的 elicitation 需要现代 MCP 服务器，默认开启。在服务器上设置 `elicitation: false` 可禁用。对于旧版服务器，使用 `onElicitation` 处理器并使用 `mode: "legacy"` 代替。没有 checkpointer，请求输入的工具会以错误 `ToolMessage` 失败而不是暂停。

<McpElicitationJs />

`createMCPElicitationResume` 将答案回复给请求它的中断。响应使用服务器的请求键。使用 `createMCPElicitationResume` 构建 resume 值，而不是裸 `{ responses }` 对象，后者不说明它回复哪个中断。

每个中断的 `value` 是一个 `MCPElicitationInterrupt`: `type: "mcp_elicitation"`, `server`, `tool`（服务器的工具名称，不带前缀），`arguments`（有效工具参数），和 `requests`。当同一个智能体也可以引发 human-in-the-loop 中断时，检查 `type`。

当多个调用同时暂停时，回复每个中断。将 `createMCPElicitationResume` 返回的对象合并为一个 `Command({ resume })`，例如 `Object.assign({}, ...paused.__interrupt__!.map((q) => createMCPElicitationResume(q, answers)))`，或直到 `__interrupt__` 为空。仅回复第一个中断的恢复会保留其他中断暂停。
:::

<Note>
恢复会从头重新运行工具。服务器请求输入之前的任何工作可能会重复。确保这些工作在没有重复副作用的情况下安全重复。
</Note>

每个答案使用以下动作之一：

- **`accept`**: 提供与请求模式匹配的表单 `content`，或确认 URL 交互完成而不使用 `content`。
- **`decline`**: 拒绝提供请求的信息。
- **`cancel`**: 指示用户取消了交互。

适配器将答案转发给服务器，服务器决定工具调用如何结束。

:::python
仅以这种方式回复 elicitation。如果服务器请求 [ sampling](https://modelcontextprotocol.io/specification/2025-06-18/client/sampling) 或 [roots](https://modelcontextprotocol.io/specification/2025-06-18/client/roots) 会引发错误，因为现代、无会话的协议没有这些请求的实时反向通道。参见 [Sampling and roots](/langchain/oss/migrate/langchain-mcp-adapters#采样和根)。
:::

:::js
仅以这种方式回复 elicitation。适配器在每个调用上仅声明 elicitation 功能，因此需要 [ sampling](https://modelcontextprotocol.io/specification/2025-06-18/client/sampling) 或 [roots](https://modelcontextprotocol.io/specification/2025-06-18/client/roots) 的工具会以错误 `ToolException` 失败，`createAgent` 会将错误 `ToolMessage` 返回给模型。参见 [Sampling and roots](/langchain/oss/migrate/langchain-mcp-adapters#采样和根)。
:::

<Note>
基于中断的 elicitation 回复服务器将其请求作为 `InputRequiredResult` 返回的情况。仅通过旧版握手会话推送 elicitation 的服务器不能以这种方式回复。
</Note>
