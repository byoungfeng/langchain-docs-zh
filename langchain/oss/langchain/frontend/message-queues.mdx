消息队列允许用户连续发送多条消息，而无需等待智能体完成当前消息的处理。每条消息都会立即被接受，排队等待活跃线程处理，并按顺序处理，为您提供对待处理工作的完全可见性和控制权。

## 为什么使用消息队列？

在典型的聊天界面中，用户必须等待智能体完成响应后才能发送另一条消息。这在以下几种场景中会带来摩擦：

- **批量提问**：用户希望一次性提出五个相关的问题，而不是等待每个答案
- **后续链**：在智能体仍在工作时提交澄清或附加上下文
- **自动化测试序列**：程序性地发送一系列提示词以验证智能体行为
- **数据输入工作流**：按顺序输入结构化数据以进行处理

消息队列通过立即接受所有提交并按顺序处理它们来解决这个问题。

这是一种智能体用户体验原语，而不是一个装饰性的聊天功能。SDK将队列作为流控制器的一部分进行跟踪，因此您的UI可以显示待处理的工作、取消过期的请求，并在当前运行继续时保持作曲家活跃。

## 工作原理

当您希望提交等待当前正在运行的请求时，请传递 `multitaskStrategy: "enqueue"`。在智能体处理期间，排队提交的请求会被添加到活跃线程的队列中。一旦当前运行完成，下一个排队消息将自动被派发。

使用您的框架的配套队列助手读取队列状态：

| 属性 | 类型 | 描述 |
|---|---|---|
| `queue.entries` | `SubmissionQueueEntry[]` | 所有待处理队列条目的数组 |
| `queue.size` | `number` | 当前队列中的条目数量 |
| `queue.cancel(id)` | `(id: string) => Promise<void>` | 通过ID取消特定的排队条目 |
| `queue.clear()` | `() => Promise<void>` | 取消所有排队条目 |

每个 @[SubmissionQueueEntry] 对象包含：

| 字段 | 类型 | 描述 |
|---|---|---|
| `id` | `string` | 此队列条目的唯一标识符 |
| `values` | `object` | 提交的输入值（包括消息） |
| `options` | `object` | 提交时传递的任何附加选项 |
| `createdAt` | `string` | 条目创建时的ISO时间戳 |

## 设置 `useStream`

将 @[`useStream`] 连接到您的智能体，然后将其与您的框架的提交队列助手配对。在运行进行中调用 `stream.submit()` 发送消息；在应等待当前请求的提交中传递 `multitaskStrategy: "enqueue"`。读取 `queue.entries` 和 `queue.size` 以渲染待处理的工作，并使用 `queue.cancel()` 或 `queue.clear()` 在它们开始处理之前删除项目。

import { useStream, useSubmissionQueue } from "@langchain/react";

function Chat() {
  const stream = useStream<typeof myAgent>({
    apiUrl: "http://localhost:2024",
    assistantId: "simple_agent",

  const queue = useSubmissionQueue(stream);

    stream.submit({
      messages: [{ type: "human", content: text }],

  const entries = queue.entries;

  return (

      <MessageList messages={stream.messages} />

    </div>
  );
}

## 显示队列

构建一个 `QueueList` 组件，显示每条待处理消息并附带取消按钮。这使用户能够了解正在等待的内容，并能够删除他们不再需要的项目。

```tsx
function QueueList({ entries, queue }) {
  return (
    <div className="queue-panel">
      <div className="queue-header">
        <span>Queued messages ({entries.length})</span>
        <button onClick={() => queue.clear()}>Clear all</button>
      </div>
      <ul className="queue-entries">
        {entries.map((entry) => {
          const text = entry.values?.messages?.at(-1)?.content ?? "Pending...";
          return (
            <li key={entry.id} className="queue-entry">
              <span className="queue-text">{text}</span>
              <span className="queue-time">
                {new Date(entry.createdAt).toLocaleTimeString()}
              </span>
              <button
                className="queue-cancel"
                onClick={() => queue.cancel(entry.id)}
              >
                Cancel
              </button>
            </li>
          );
        })}
      </ul>
    </div>
  );
}
```

<Tip>
显示每个排队消息的前几个字符作为预览，以便用户可以快速识别要取消的项目，而无需阅读完整消息。
</Tip>

## 取消排队消息

您有两个级别的取消：

### 取消单个条目

通过其ID从队列中删除特定消息。智能体会跳过它并移动到下一个条目。

```ts
await queue.cancel(entryId);
```

### 清空整个队列

一次性删除所有待处理消息。当用户更改上下文或希望重新开始时很有用。

```ts
await queue.clear();
```

<Note>
取消队列条目仅影响**尚未开始处理**的消息。如果智能体已经在处理一条消息，从队列中取消它将没有任何效果。使用 `stream.stop()` 来中断当前运行。
</Note>

## 使用 `onCreated` 链接后续提交

当创建新的运行时，`onCreated` 回调会触发，为您提供通过编程方式提交后续消息的钩子。这对于构建多步骤工作流很有用，其中下一个问题取决于先前提交被接受。

```ts
stream.submit(
  { messages: [{ type: "human", content: "What is quantum computing?" }] },
  {
    onCreated(run) {
      console.log("Run created:", run.runId);
      // Chain a follow-up
      stream.submit({
        messages: [{ type: "human", content: "Give me a simple analogy." }],
      });
    },
  }
);
```

这种模式自然地填充了队列。第一条消息立即开始处理，后续消息在它后面排队。

## 开始新的线程

当用户希望开始一次全新的对话时，更新您传递到流的反应式 `threadId`。传递 `null` 会清除当前线程绑定；下一个提交将创建一个新的线程。

## 最佳实践

- **限制队列大小**：虽然客户端没有队列大小的硬限制，但请注意，非常大的队列可能会降低用户体验。当队列超过合理阈值（例如，10个项目）时，考虑显示警告。
- **显示队列位置**：为每个排队项目编号，以便用户知道处理顺序。
- **保持输入焦点**：提交后保持输入字段聚焦，以便用户可以立即输入下一条消息。
- **动画过渡**：当它们开始处理时，平滑地将项目从队列面板移动到消息列表中。
- **优雅地处理错误**：如果排队消息失败，请在不阻塞后续队列条目的情况下显示错误。
- **防抖快速提交**：对于自动化或程序性提交，在消息之间添加小的延迟，以避免使服务器不堪重负。
