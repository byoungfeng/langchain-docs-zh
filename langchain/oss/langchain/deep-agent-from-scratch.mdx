本指南使用 `create_agent` 和 Deep Agents 中间件从基础构建一个数据分析智能体。

`create_agent` 和 `create_deep_agent` 都能让你对工具、记忆等细节进行精细控制。
两者之间的主要区别在于 Deep Agents 已内置多种常用功能，例如规划、文件系统工具和子智能体。
如果 Deep Agents 默认的 harness 不符合你的需求，本指南将展示如何从 `create_agent` 开始，逐步组装 harness，让你清楚每个组件的作用，并只替换你用例所需的组件。

按照本指南构建一个智能体，实现：

1. 接收 CSV 文件进行分析
2. 在隔离沙箱中编写和执行 Python 代码
3. 将可视化工作委托给专业子智能体
4. 从技能文件加载数据分析模式

最终栈结构与 `create_deep_agent` 默认组装的结构一致。

## 你将学到什么

每一步为同一个数据分析智能体添加一项功能：

| 步骤 | 缺少它会遇到的问题 | 你添加的内容 |
|------|-------------------|--------------|
| 最小智能体 | — | 基线循环：模型 + 工具，无 harness |
| 沙箱 + 文件系统 | 智能体无法读取 CSV 或运行 Python | 隔离的 [backend](/langchain/oss/deepagents/backends) + 文件和执行工具 |
| 摘要 | 长会话超出上下文限制 | 自动历史压缩 |
| 技能 | 领域规则使系统提示词臃肿 | 通过 [渐进式披露](/langchain/oss/langchain/multi-agent/skills-sql-assistant) 的按需专业知识 |
| 子智能体 | 图表迭代阻塞主线程 | 隔离的工作线程 + 并行委托 |

## 添加技能

[技能](/langchain/oss/langchain/multi-agent/skills-sql-assistant)提供了一种在需要时通过渐进式披露为智能体提供按需领域知识的方法。技能可以包含多步工作流、规则和约定。通过将信息放在技能中，它不会默认添加到系统提示词中，这确保了 Token 仅在需要技能信息执行任务时使用。

当智能体启动时，它只看到每个技能的轻量级元数据。当任务需要技能时，智能体按需加载完整的技能文件。

在技能目录中创建一个技能文件：

```
skills/
  pandas-patterns/
    SKILL.md
```

```markdown
---
name: pandas-patterns
description: Common pandas and matplotlib patterns for data analysis and visualization
---

## Data loading
Use `pd.read_csv()` for CSV files. Always check `df.info()` and `df.describe()` first.

## Visualization
Use `matplotlib` for bar charts, `seaborn` for statistical plots.
Save figures with `plt.savefig("output.png", dpi=150, bbox_inches="tight")`.

## Reporting
Write a markdown summary to `report.md` alongside any generated charts.
```

## 添加可视化子智能体

某些任务会产生大量中间输出（脚本草稿、失败运行、文件读取），如果保留在一个线程中，会挤占主智能体的上下文。一个 [子智能体](/langchain/oss/deepagents/subagents)在其自己的上下文窗口中运行，因此监督者只看到最终结果，而不是每一步的每个工具调用。这使主要分析保持专注，并为后续问题留出空间。

使用子智能体是合理的示例之一，即图表生成。绘图通常意味着迭代 Python 脚本、安装包并读取错误输出，直到图形准备好。以下 `visualizer` 子智能体可以独立处理这项工作，而主智能体可以继续规划和分析。使用 @[`TodoListMiddleware`]，主智能体还可以并行委派图表工作，而不是在每个绘图上阻塞。
