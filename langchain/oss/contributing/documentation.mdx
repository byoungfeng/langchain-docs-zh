## 快速入门 - 本地开发

要运行本地文档预览：

```bash
git clone https://github.com/langchain-ai/docs.git
```

```bash
cd docs
```

使用 [mise](https://mise.jdx.dev/getting-started.html) 安装固定工具链，它会从 `.mise.toml` 读取 Python、Node.js、uv、Vale 和 Mintlify CLI 的版本，并安装仓库的 git 钩子：

```bash
mise trust && mise install
```

```bash
make install
```

```bash
make dev
```

这会在 `http://localhost:3000` 启动开发服务器并启用热重载。在 `src/` 中编辑文件，即可立即看到更改。

<Tip>
    **使用 AI 编码智能体？**

    - 安装 [LangChain 文档 MCP 服务器](/use-these-docs)，以让您的智能体访问最新的 LangChain 文档和示例。

      <ConnectDocsMcpPrompt />
    - 安装 [LangChain 技能](https://github.com/langchain-ai/langchain-skills)，以提高您的智能体在 LangChain 生态系统任务上的性能，然后点击此页面右上角的 **复制页面** 按钮，并将原始内容粘贴到您的智能体中，让它自动设置您的环境。

      <InstallLangchainSkillsPrompt />
    - 此仓库在 `.agents/skills/` 中自带其自身的作者技能，涵盖页面创建、导航位置和重定向。大多数智能体会直接读取该路径。对于 Claude Code，运行 `make skills` 以链接它们。
</Tip>

<Tip>
如果您在本地预览时遇到问题，请尝试运行 `mint update` 以确保您使用的是最新版本的 Mintlify。
</Tip>

<Accordion title="Prerequisites">
    **推荐：** 运行 `mise trust && mise install` 以一次性获取所有固定版本。`.mise.toml` 是工具链的规范固定版本，其 postinstall 钩子会连接 pre-commit 和 pre-push 钩子。

    **必需：**
    - Python 3.13+
    - [uv](https://docs.astral.sh/uv/) 0.9.26 或更高版本 - Python 包管理器
    - [Node.js](https://nodejs.org/en) 22.x 和 npm。Mintlify 不支持 Node 25 或更高版本
    - [Make](https://www.gnu.org/software/make/)
    - [Git](https://git-scm.com/)

    **可选：**
    - [markdownlint-cli](https://github.com/igorshubovych/markdownlint-cli) - `npm install -g markdownlint-cli`
    - [Mintlify MDX VSCode 扩展](https://www.mintlify.com/blog/mdx-vscode-extension)
</Accordion>

## 编辑文档

<Accordion title="Quick edits on GitHub">
    对于拼写错误或小更改，无需本地设置即可直接在 GitHub 上编辑：

    1. 点击任何页面底部的 **在 GitHub 上编辑此页面**。
    1. 将其 fork 到您的个人账户。
    1. 在 GitHub 的网络编辑器中做出更改。
    1. 创建一个拉取请求。
</Accordion>

<Note>
    **仅编辑 `src/` 中的文件**-- `build/` 目录是自动生成的。
</Note>

1. 按照我们的 [写作标准](#写作标准) 在 `src/` 中编辑文件。
1. 提交前运行 [质量检查](#运行质量检查)。
1. 创建拉取请求以供审核。

<Note>
    所有拉取请求都必须链接到一个已获维护者批准解决方案的问题或讨论。请参阅我们的 [拉取请求要求](/langchain/oss/contributing/overview#pull-request-requirements)。
</Note>

<Accordion title="Create a sharable preview build (LangChain team only)">
    当您创建或更新拉取请求时，会自动生成一个 [预览分支/ID](https://github.com/langchain-ai/docs/actions/workflows/create-preview-branch.yml)。会在拉取请求上留下一个包含 ID 的评论。

    1. 从评论中复制预览分支的 ID
    2. 在 [Mintlify 控制面板](https://dashboard.mintlify.com/langchain-5e9cc07a/langchain-5e9cc07a?section=previews) 中，点击 **创建预览部署**
    3. 输入预览分支的 ID 并点击 **创建部署**
    4. 选择预览并点击 **访问** 以查看

    要使用最新更改重新部署，请点击控制面板上的 **重新部署**。
</Accordion>

### 运行质量检查

在提交更改前，确保您的代码通过格式化和 linting 检查：

```bash
# Check broken links and anchors
make broken-links-with-anchors

# Format code automatically
make format

# Check for linting issues
make lint

# Fix markdown issues
make lint_md_fix

# Run tests to ensure your changes don't break existing functionality
make test
```

更多详情，请参阅 `README` 中的 [可用命令](https://github.com/langchain-ai/docs?tab=readme-ov-file#available-commands) 部分。

<Important>
    所有拉取请求都会通过 CI/CD 自动检查。相同的 linting 和格式化标准将被强制执行，如果这些检查失败，则无法合并 PR。
</Important>

### 同时放置 Python 和 JavaScript/TypeScript 内容

所有文档必须尽可能同时使用 Python 和 JavaScript/TypeScript 编写。为此，我们使用自定义的行内语法来区分应在一种或两种语言中显示的章节：

```mdx
\:::python
Python-specific content. In real docs, the preceding backslash (before `python`) is omitted.
\:::

\:::js
JavaScript/TypeScript-specific content. In real docs, the preceding backslash (before `js`) is omitted.
\:::

Content for both languages (not wrapped)
```

这将生成两个输出（每种语言一个）在 `/oss/python/concepts/foo.mdx` 和 `/oss/javascript/concepts/foo.mdx`。每个输出的页面都需要添加到 `/src/docs.json` 文件中，才能包含在导航中。

<Note>
    我们不希望内容的缺失阻碍贡献。如果某个功能仅在一种语言中可用，可以仅在该语言中提供文档，直到另一种语言赶上。在这种情况下，请添加一条注释，说明该功能在另一种语言中尚未可用。

    如果您需要在 Python 和 JavaScript/TypeScript 之间翻译内容，请到 [社区 Slack](https://www.langchain.com/join-community) 中提问，或在您的 PR 中标记维护者。

## 质量标准

### 一般指南

<AccordionGroup>
    <Accordion title="Avoid duplication">
        多个页面覆盖相同内容难以维护并造成混淆。每个概念或功能应只有一个权威页面。链接到其他指南而不是重复解释。
    </Accordion>

    <Accordion title="Link frequently">
        文档章节并非孤立存在。频繁链接到其他章节，以便用户学习不熟悉的主题。这包括链接到 API 参考文档和概念章节。
    </Accordion>

    <Accordion title="Be concise">
        采用少即是多的方法。如果另一个章节有良好的解释，请链接到它而不是重复解释，除非您的内容提供了新的角度。
    </Accordion>
</AccordionGroup>

### 无障碍要求

确保文档对所有用户都无障碍：

- 使用标题和列表构建内容结构，便于扫描
- 使用具体的、可操作的链接文本，而不是“点击这里”
- 为所有图像和图表提供描述性替代文本

### 交叉引用

使用一致的交叉引用将文档与 API 参考文档连接起来。

**从文档到 API 参考文档：**

使用 `@[]` 语法链接到 API 参考文档页面：

```mdx
See \@[`ChatAnthropic`] for all configuration options.

The \@[`bind_tools`][ChatAnthropic.bind_tools] method accepts...
```

构建流程会根据当前语言范围（Python 或 JavaScript）将这些内容转换为标准的 Markdown 链接。例如，`\@[ChatAnthropic]` 会根据正在构建的文档版本，变成指向 Python 或 JS API 参考页面的链接，**但前提是 `link_map.py` 文件中存在对应的条目！** 详细信息请见下文。

<Accordion title="How autolinks work">

`@[]` 语法由 [`handle_auto_links.py`](https://github.com/langchain-ai/docs/blob/main/pipeline/preprocessors/handle_auto_links.py) 处理。它会查询 [`link_map.py`](https://github.com/langchain-ai/docs/blob/main/pipeline/preprocessors/link_map.py) 中的链接键，该文件包含了 Python 和 JavaScript 范围的字典映射。

**支持的格式：**

| 语法 | 结果 |
|------|------|
| `\@[ChatAnthropic]` | 显示文本为 "ChatAnthropic" 的链接 |
| `` \@[`ChatAnthropic`] `` | Link with `` `ChatAnthropic` ``（代码格式化）作为文本 |
| `\@[text][ChatAnthropic]` | 链接文本为 "text"，链接映射中的键为 `ChatAnthropic` |
| `\\@[ChatAnthropic]` | 转义：渲染为字面值 `\@[ChatAnthropic]`（无链接——本页正在使用的就是这个功能！） |

**添加新链接：**

如果映射中找不到链接，它将在输出中保持原样。要添加新的自动链接：

1. 打开 `pipeline/preprocessors/link_map.py`
2. 在 `LINK_MAPS` 中为适当的范围（`python` 或 `js`）添加条目
3. 键是用于 `\@[key]` 或 `\@[text][key]` 中的链接名称，值是相对于参考主机的路径

</Accordion>

:::python
**从 API 参考占位符到 OSS 文档：**

已发布的 Python API 参考中的交叉链接和深度锚点是在此仓库外部生成的。如果来自 reference.langchain.com 到 docs.langchain.com 的链接错误或过时，请 [打开问题](https://github.com/langchain-ai/docs/issues/new?template=04-reference-docs.yml) 并提供源 URL 和目标 URL。
:::
