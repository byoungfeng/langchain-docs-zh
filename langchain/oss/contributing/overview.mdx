## 问题和拉取请求要求

您可以直接提交针对拼写错误和小修复的拉取请求，无需问题、维护者预先批准或分配。

<Warning>
    **较大的更改，如新的教程、指南或概念页面，在您打开拉取请求之前需要关联的问题和维护者的批准。** 等待维护者批准您的方案并将问题分配给您。在批准和分配之前打开的较大 PR 可能会被自动关闭，并且不会在分配之前进行审查。
</Warning>

所有拉取请求都应展示有意义的努力和背景理解。**如果创建拉取请求所需的努力小于维护者审查它所需的努力，那么该贡献不应提交。** 低效的过路贡献——无论其产生方式如何——通常在背景相关性、准确性和质量方面有所欠缺。大规模的自动化贡献是对我们人类努力的拒绝服务攻击。

<Warning>
    **我们优先处理由实际使用动机驱动的问题。** 问题看板是分配维护者注意力的机制。它们不是每个静态可发现缺陷的全面目录。请避免在首先亲自验证它们并将它们基于 LangChain 的公共 API 的实际使用，而没有提交由 (AI) 代码扫描发现的问题。如果维护者怀疑问题尚未得到验证，它可能会在未经审查的情况下关闭，并且作者账户可能会被阻止。
</Warning>

所有外部拉取请求必须满足以下要求：

* 对于较大的变更，在打开 PR 之前，需要链接到一个由维护者已批准你的方法并分配给你的问题。拼写错误和小型修复除外。
* PR 必须填写仓库的 PR 模板。
* 用于全新功能或行为改变 Bug 修复的 PR 应包含一个 `## Release note` 部分，用适合发布说明的语言说明用户可见的变更。

维护者保留在不加评论的情况下关闭 PR 的权利。**我们将关闭看起来是低效垃圾的 PR 和问题。**

## 语言政策

所有贡献——问题、PR、代码评审和讨论——都必须使用英语。这使沟通对全球贡献者基础来说是可访问和可搜索的。

如果你的第一语言不是英语，不用担心。我们重视清晰的沟通胜过完美的语法，欢迎使用翻译工具。

## LLM 的可接受使用方式

你可以使用 AI 助手来帮助你起草或修订贡献，当**验证每一个变更**时：运行和测试代码，对照代码库和官方提供者文档检查事实，并确保结果与仓库风格一致。不要提交大量未经评审的生成内容。无论它们是如何产生的，我们都会关闭看起来是低效或垃圾的 PR。
