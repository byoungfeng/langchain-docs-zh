    ## `@langchain/core` v1.3.0

    在 [事件流](/langchain/oss/langchain/event-streaming) 中，工具调用参数现在作为 `tool-call-delta` 事件流式传输。每个事件只包含参数的新部分，就像 `text-delta` 对文本做的那样。早期版本发送 `block-delta` 事件，重复到目前为止所有的参数。

    ### 在服务器之前升级客户端

    低于以下版本的客户端不处理 `tool-call-delta`。例如，`@langchain/react` 的早期版本可能会停止更新一个 `useMessages` 视图。[智能体服务器](https://docs.langchain.com/langsmith/agent-server) 会不变地传递事件，因此服务器上的包版本决定了客户端接收哪些事件。

    1. 在每个读取流的客户端中，将 `@langchain/react`、`@langchain/vue`、`@langchain/svelte` 或 `@langchain/angular` 升级到 1.2.6 或更高版本。
    2. 在服务器上将 `@langchain/core` 升级到 1.3.0 或更高版本。同时升级服务器使用的每个提供程序包，因为早期版本仍然发送 `block-delta`：
        - `@langchain/openai` 到 1.7.0 或更高版本
        - `@langchain/anthropic` 到 1.6.0 或更高版本
        - `@langchain/aws` 到 1.5.0 或更高版本
        - `@langchain/xai` 到 1.5.0 或更高版本

    升级 `langchain`、`deepagents` 或提供程序包可能会引入 `@langchain/core` 1.3.0。为了在升级所有客户端之前阻止服务器，请在 `package.json` 中将 `@langchain/core` 固定为 `<1.3.0`。步骤 2 中的提供程序版本需要 `@langchain/core` 1.3.0，因此在存在固定的情况下无法安装它们。
</Update>

<Update label="Oct 15, 2026" tags={["langchain"]} rss={{ title: "Oct 15, 2026 - langchain" }}>
    ## `langchain` v1.5.18

    `humanInTheLoopMiddleware` 现在可以在每次工具调用时暂停。设置 `interruptMode: "per_call"` 和每个受保护的调用会引发自己的中断，您通过中断 ID 来响应。批量模式仍然是默认模式。

    ```typescript
    humanInTheLoopMiddleware({ interruptOn: {...}, interruptMode: "per_call" });
    ```

    ### 功能

    - **类型化答案**: 每个中断都包含一个 `response_schema`，列出了调用允许的决策，因此客户端可以根据模式构建其表单。参见 [读取响应模式](/langchain/oss/langchain/human-in-the-loop#读取响应模式)。
    - **保存前检查**: LangGraph 在保存无效答案之前会拒绝它，因此您可以更正它并再次回答相同的中断。参见 [更正无效答案](/langchain/oss/langchain/human-in-the-loop#修正无效答案)。
    - **编辑保留在被调用的工具上**: 一个 `edit` 不能切换工具，并且其参数会根据工具自己的模式进行检查。
    - **`respond` 处处可用**: `interruptOn: { tool: true }` 现在允许两种模式中的每个决策，包括 `respond`，就像 Python 一样。

    为新智能体使用按调用模式。LangChain 计划在下一个主要版本中将它设为默认值。参见 [每次工具调用暂停一次](/langchain/oss/langchain/human-in-the-loop#每次工具调用暂停一次) 和 [人机交互概述](/langchain/oss/concepts/human-in-the-loop)。
</Update>

<Update label="Mar 24, 2026" tags={["deepagents"]} rss={{ title: "Mar 24, 2026 - deepagents" }}>
    ## `deepagents` v1.9.0-alpha.0

    `deepagents` v1.9.0 的 Alpha 版本。

    - **[异步子智能体](/langchain/oss/deepagents/async-subagents)**: 深度智能体可以启动非阻塞的后台任务，因此用户可以在子智能体并发工作时继续与智能体交互。需要 [LangSmith 部署](https://docs.langchain.com/langsmith/deployment) 来支持子智能体。

    - **[后端](/langchain/oss/deepagents/backends) 协议 v2**: 我们引入了一个新的 v2 后端协议（`BackendProtocolV2`），并对深度智能体后端接口进行了向后兼容的更改。主要更改：
      - **结构化结果类型**: 所有方法现在返回结构化的 `Result` 对象（例如，`ReadResult`、`LsResult`、`GrepResult`、`GlobResult`），通过 `error` 字段提供一致的错误处理，而不是返回原始值或抛出异常。
      - **多模态文件支持**: `read()` 返回一个包含 `.content` 字段的 `ReadResult`，而不是纯字符串。对于二进制文件（图像、PDF、音频、视频），完整的原始 `Uint8Array` 内容通过 `readRaw()` 返回，使智能体能够原生处理多模态文件。
      - **简化方法名称**: `lsInfo` -> `ls`, `grepRaw` -> `grep`, `globInfo` -> `glob`。
      - **向后兼容**: 使用 `adaptBackendProtocol` 可以将现有的 v1 后端适配到 v2 接口。v1 接口（`BackendProtocolV1`、`SandboxBackendProtocolV1`）已弃用但保留以保持兼容性。
</Update>
<Update label="Jan 14, 2026" tags={["langgraph"]} rss={{ title: "Jan 14, 2026 - langgraph" }}>
    ## v1.1.0

    ### `@langchain/langgraph`

    引入 **StateSchema** - 一种更干净、库无关的方式来定义图状态，它适用于任何 [标准模式](https://github.com/standard-schema/standard-schema)-兼容的验证库。

    ### 标准JSON模式支持

    LangGraph 现在支持 [标准 JSON Schema](https://standardschema.dev/json-schema)，这是一个由 Zod 4、Valibot、ArkType 及其他模式库实现的开放规范。这意味着您可以在没有锁定的情况下使用您喜欢的验证库：

    ```typescript
    import { z } from "zod"; // or valibot, arktype, etc.
    import { StateSchema, ReducedValue, MessagesValue } from "@langchain/langgraph";

    const AgentState = new StateSchema({
      messages: MessagesValue,
      currentStep: z.string(),
      count: z.number().default(0),
      history: new ReducedValue(
        z.array(z.string()).default(() => []),
        {
          inputSchema: z.string(),
          reducer: (current, next) => [...current, next],
        }
      ),
    });

    // Type-safe state and update types
    type State = typeof AgentState.State;
    type Update = typeof AgentState.Update;

    const graph = new StateGraph(AgentState)
      .addNode("agent", (state) => ({ count: state.count + 1 }))
      .addEdge(START, "agent")
      .addEdge("agent", END)
      .compile();
    ```

    ### 新的状态值原语

    * **ReducedValue**: 定义具有自定义累加值的字段。支持为类型安全的累加器输入提供单独的输入和输出模式。
    * **UntrackedValue**: 定义在执行期间存在但从未检查点的临时状态 - 对于数据库连接、缓存或仅限运行时配置很有用。
    * **MessagesValue**: 一个预构建的 `ReducedValue`，用于聊天消息，带有标准的消息累加器。

    ### 类型辅助导出

    新导出的类型工具，用于在图构建器外部对函数进行类型化：

    * `GraphNode<Schema, Nodes?, Config?>` - 使用完整推断类型化节点函数
    * `ConditionalEdgeRouter<Schema, Nodes?>` - 类型化条件边路由器

    ```typescript
    // Type standalone node functions
    const myNode: GraphNode<typeof AgentState> = (state, config) => {
      return { count: state.count + 1 };
    };

    // Use schema type helpers directly
    const processState = (state: typeof AgentState.State) => {
      console.log(state.count);
    };
    ```

    现有的 `Annotation` 和基于 zod 的 API 继续按原样工作不变 - `StateSchema` 是为那些更喜欢模式优先定义的用户提供的额外选项。

    <Card title="Learn more about StateSchema" icon="book" href="/langchain/oss/langgraph/graph-api#模式">
      查看完整文档，了解如何使用 StateSchema、ReducedValue 和 UntrackedValue 定义图状态。
    </Card>
    <Card title="Learn about type utilities" icon="code" href="/langchain/oss/langgraph/graph-api#类型工具">
      使用 GraphNode 和 ConditionalEdgeRouter 在图构建器外部类型化函数。
    </Card>
</Update>

    ## v1.1.0

    * [模型配置文件](/langchain/oss/langchain/models#模型配置文件): 对话模型现在通过 `.profile` 获取器暴露支持的特性和功能。这些数据来自 [models.dev](https://models.dev)，一个提供模型能力数据的开源项目。
    * [模型重试中间件](/langchain/oss/langchain/middleware/built-in#模型重试): 新的中间件，用于自动重试失败的模型调用，并具有可配置的指数退避，提高智能体可靠性。
    * [内容审核中间件](/langchain/oss/langchain/middleware/built-in#提供商特定中间件): OpenAI 内容审核中间件，用于检测和处理智能体交互中的不安全内容。支持检查用户输入、模型输出和工具结果。
    * [摘要中间件](/langchain/oss/langchain/middleware/built-in#摘要): 更新为支持使用模型配置文件进行上下文感知摘要的灵活触发点。
    * [结构化输出](/langchain/oss/langchain/structured-output): `ProviderStrategy` 支持（原生结构化输出）现在可以从模型配置文件中推断。
    * [`SystemMessage` for `createAgent`](/langchain/oss/langchain/middleware/custom#动态提示词): 支持将 `SystemMessage` 实例直接传递给 `createAgent` 的 `systemPrompt` 参数，以及一个新的 `concat` 方法用于扩展系统消息。启用高级功能，如缓存控制和结构化内容块。
    * [动态系统提示中间件](/langchain/oss/langchain/short-term-memory): 从 `dynamicSystemPromptMiddleware` 返回的值现在纯粹是附加的。当返回一个 @[`SystemMessage`] 或 `string` 时，它们会与现有的系统消息合并，而不是替换它们，这使得组合多个修改提示的中间件更加容易。
    * **兼容性改进:** 修复了结构化输出和工具模式中 Zod v4 验证错误的错误处理，确保详细错误消息正确显示。
</Update>
