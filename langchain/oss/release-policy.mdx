LangGraph 遵循结构化发布策略，确保用户构建生产级应用时的稳定性和可预测性。  

## 发布节奏  

我们预计**主要版本**间隔至少6-12个月，以保障生产应用稳定性。  

**次要版本**通常每1-2个月发布新功能与改进。  

**补丁版本**按需发布（通常每周一次），用于修复缺陷和漏洞。  

## API 稳定性  

### 稳定 API  

无特殊前缀的API均视为稳定，适用于生产环境。我们会在主版本内保持稳定功能向后兼容。  

### Beta 功能  

文档中标记为 `beta` 的功能特性：  
- 功能完整且经过测试  
- 在理解可能变更的前提下可用于生产  
- 根据用户反馈可能进行次要API调整  

### 实验性功能  

标记为 `experimental` 或 `alpha` 的功能：  
- 处于活跃开发中  
- 可能发生重大变更或移除  
- 建议谨慎用于生产环境  

### 内部 API  

以下两种情况视为内部API：  
- 前缀为下划线（`_`）  
- 文档明确标记为内部  
- API特性：  
  - 不属于公共API  
  - 可能无通知变更  
  - 不应直接调用  

## 弃用政策  

弃用功能时遵循以下流程：  
1. **弃用通知**: 明确标记为弃用并提供迁移指引  
2. **缓冲期**: 弃用功能在至少一个次要版本中保持可用  
3. **移除**: 仅在主版本发布时移除  
4. **迁移支持**: 提供迁移指南，必要时提供自动化工具

## 重大版本变更

重大版本中才会引入破坏性变更，包括：

- 移除已弃用 API
- 修改必需参数
- 影响现有应用行为的默认行为变更
- Python/Node.js 最小版本更新

## 迁移支持

进行重大版本升级时，我们提供：

- 完整的迁移指南
- 可行时提供的自动化迁移脚本
- 前一重大版本延长支持期
- 所有破坏性变更的清晰文档
